本机运行的 AI 聊天机器人与任务助手。预装可删除的初音未来人格，支持独立聊天、QQ 接入、记忆、黑话学习、人格蒸馏和管理员电脑任务。

## 第一次使用

1. **打开软件并设置密码**：首次在运行电脑上设置至少 8 个字符的登录密码。只在本机使用时，也可明确选择“仅本机免密”；此模式关闭远程入口。
2. **添加模型供应商**：在快速入门点击“添加供应商并选择模型”，填写服务商提供的 **API 地址** 和 **API Key**。地址以服务商文档为准，兼容接口通常以 `/v1` 结尾，不要填网页聊天地址。
3. **获取并选择模型**：系统从实际返回的列表推荐并预选聊天模型，也可改选或手填。点击“测试并用于聊天”，短文本测试成功后自动设为默认聊天模型；服务不提供列表接口时，可以手填准确的模型名。
4. **开始聊天**：打开“Chat 工作台”，新建对话，发送“你好”；也可先建项目，将相关会话放在一起。网页支持增量预览，完成后显示校验后的完整回复；首次不必配置 QQ、电脑能力或其他模型分工。

后续在“机器人配置 → 模型”管理多个来源与模型，在聊天顶栏为单个会话切换模型。手动新增供应商只保存连接；还需选择“设为聊天模型”或指定本会话模型。新配置未单独指定判断、记忆和整理模型时继承全局对话模型；完整旧版基础连接继续保留，明确停用或缺失的选择不会悄悄替换。只有实际支持工具调用、图片等能力的模型，才能使用对应功能。

**嵌入模型**：打开“机器人配置 → 模型 → 嵌入模型 → 添加嵌入模型”，复用已有供应商或填写新连接，获取型号或手动输入，点击“保存、测试并启用检索”。系统实际调用 `/embeddings`，验证向量后启用记忆检索；无需再去高级设置指定路由。页面直接显示当前模型和开关，也可单独测试、调整参数或关闭。此模型独立于聊天，测试同样计入模型用量。

桌面窗口依赖 Microsoft Edge WebView2 运行时。缺少组件或桌面加载失败时会自动切换系统浏览器，并提示切换结果；也可运行 `shiori.exe --browser`。有托盘时关闭窗口会继续运行，从托盘选择“退出”才完全停止。

## 接入 QQ

### 本机 NapCat / SnowLuma

1. 自行启动连接器，完成 QQ 登录与必要的设备验证。
2. 在快速入门选择接入方式，使用默认黑名单，点击“保存并自动配对”；无需先填 QQ 号或群号。旧白名单会保留，可明确切换。
3. 填入连接器的本机 WebUI 地址与管理口令；SnowLuma 多账号时选择实际使用的账号。
4. Shiori 会通过连接器管理接口创建专属**反向 WebSocket**。口令不保存，其他连接配置保留。
5. 等待页面显示实际在线，再用自己的账号私聊或在未屏蔽的群里 @ 机器人。收到的聊天自动收集到“群与会话”，未单独设置时继承默认配置。

默认探测 NapCat 的 `http://127.0.0.1:6099`、SnowLuma 的 `http://127.0.0.1:5099`，可手动修改。自动配对适用于本机回环地址；其他环境可展开手动配置，将页面显示的 `/onebot/v11/ws` 地址与相同 Access Token 填入连接器。扫码登录、连接器安装和初始化需要自行完成。

### QQ 官方机器人

在 QQ 开放平台申请应用，在“机器人配置 → QQ 连接”填写 AppID、AppSecret 并启用。官方机器人使用平台 OpenID，不能直接把普通 QQ 数字号填入 OpenID 名单；可用场景受平台权限与审核规则限制。

**在线但不回复时**：先看 QQ 设置中的“消息接收与回复”，确认是否收到消息、是否被名单或回复规则跳过；再打开“运行日志”检查模型与发送结果。详细排障见[使用指南](docs/USER_GUIDE.md#9-常见卡点)。

## 管理员与电脑任务

“允许聊天”和“管理员”分别设置。默认管理员 `shiori` 代表通过管理台认证的本地账户；QQ 管理员可以添加多个，按平台真实发送者 ID 识别。昵称、群主身份、转发或引用不会授予权限。不确定账号标识时，可使用“绑定我的 QQ”：在本地开启60秒快速配对，由目标 QQ 私聊发送配对码即完成绑定；也保留手动核对模式。

在“机器人配置 → 电脑与管理员”开启能力、选择工作目录，然后在聊天中选择“电脑任务”，或由 QQ 管理员发送 `/执行 具体任务`。支持 Shell、Python、文件读取、搜索、新建与修改；新安装默认选择 Docker 隔离执行，原有本机模式不强制迁移；默认自动执行，可在任务卡片停止。`/任务 任务编号` 查看进度，`/停止 任务编号` 停止。

**本机模式的 Shell/Python 使用当前系统账户权限，工作目录不是隔离沙箱。Docker 沙箱隔离主机系统，不保护工作目录内的文件；/workspace 是可写映射，脚本可在其中增删文件。Docker 默认断网且限制资源，需本机 Linux 容器引擎及指定摘要镜像；按“检查隔离环境”返回的完整命令准备，不可用时停止任务。**只向可信管理员开放电脑能力。本版不提供鼠标键盘与屏幕截图循环；任务退出或重启后不会自动重跑。MCP 工具还受服务与工具允许列表约束；开启电脑能力且使用自动模式时，管理员的允许调用可连续执行。Docker 电脑能力开启时默认禁用沙箱外 MCP；确有需要须在高级设置明确开启，其执行仍不在代码容器内。

## 其他功能

0.1.6正式版提供可切换的公共搜索、Tavily、DeepSeek Search 和 Brave Search，入口为“机器人配置 → 网页搜索”；聊天、人格蒸馏的通用检索和兴趣探索共用搜索服务。配置、密钥和调用上限见[网页搜索说明](docs/WEB_SEARCH.md)。

- **人格与表达**：可复用机器人配置统一选择人格、模型与回应规则，聊天可批量绑定；预装初音未来，可删除全部人格后使用普通助手；可编写名称、别名与人格，支持按描述直接生成；作品角色蒸馏输出人格和角色 Skill，已有语料蒸馏仅输出人设描写。生成后先预览、试聊，再应用。
- **记忆与资料**：默认会话隔离，支持显式共享已确认记忆、来源与纠错、遗忘、可选向量检索。事件可保存概述、详细经过、参与者、地点与结果，召回结合相关片段与事件背景；旧短句保留原文，未知发生时间不编造。记忆页支持类型筛选、完整详情和来源分页。大量记忆通过候选索引及分批关系检索按需读取，缺失向量默认在有界后台队列补建。自动整理优先近期消息并保留历史进度，错误候选和撤权不会误标为完成；历史与时间检索去重，摘要失效后按原顺序恢复有效对话。附件可选本次参考、长期资料或人格蒸馏，也可预览、撤销和安全清理。
- **自然群聊与黑话**：Planner 判断消息对象和参与价值，决定回应或跳过；私聊可设必回复。本版中，@ 和名称提及可分别选择直接回复或单独交给 Planner。未开启消息防抖时，普通群消息默认集中1500毫秒或4条后判断；开启防抖后先合并同群输入，不再叠加旧收集窗口。黑话学习、理解和使用分别开关，自动候选可审核。
- **等你说完再回复**：在“机器人配置 → 回复与记忆”开启消息防抖并设置等待时间，默认关闭、开启初始值3秒。后续消息重新计时，最长等待默认30秒；QQ群聊按会话统一收集不同成员的连续消息，私聊按会话和发送者收集，本地聊天也可立即提交或取消。合并前仍分别保存原消息、时间及来源，记忆、待办和提醒命令逐条处理。
- **本地插件**：导入 ZIP、tar.gz 或 tgz 自动识别规范插件，检查后保存停用草稿；可用本地聊天创建或修改插件，保留修订并核对并发改动。运行沿用电脑权限和沙箱，不自动安装依赖。
- **表情包**：在“机器人配置 → 表情包”选择支持图片的模型，自动收集群表情并分类，支持修改语义、停用和删除；收集/发送默认开启且概率各0.1，语义不明或不合语境时不发。图片库须单独备份。
- **兴趣探索与任务**：可按兴趣收集公开资料，并列主题独立轮换；页面显示探索时间、未运行原因和逐页过滤详情。自动探索默认关闭，需同时开启全局与人格开关；待审资料不参与回答。另可管理待办和提醒，提醒需要程序运行与通道在线。
- **角色日程（0.2.1-beta）**：独立管理人格的生活档案、周表、每日安排和年度活动，支持重复纪念日、时段锁定、预演与编辑恢复。功能及回复控制默认关闭；开启后只把已保存的活动提供给聊天，可另选按忙闲状态暂存或合并 QQ 留言。虚构日记单独保存，聊天素材必须明确选择会话并分别归档，日程模型调用受每日额度和总模型预算限制。详见[使用说明](docs/CHARACTER_SCHEDULE.md)。
- **运行日志**：支持级别筛选、搜索、暂停、复制和脱敏导出。报错时优先查看这里。

## 从源码运行

Windows 安装 **Python 3.11–3.13（推荐3.12）**，完整解压对应发行版的源码包（本测试版为 `shiori-0.2.1-beta-source.zip`），或克隆本仓库。在包含 `requirements.txt` 的目录打开 PowerShell：

```powershell
# 首次：创建 .venv、安装依赖并启动，下载依赖需要网络
powershell -ExecutionPolicy Bypass -File .\scripts\setup-source.ps1
```

之后启动或停止：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Stop
```

需要指定数据目录时，首次、日常启动与停止都使用同一路径：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup-source.ps1 -DataDir 'D:\shiori-data'
powershell -ExecutionPolicy Bypass -File .\start.ps1 -DataDir 'D:\shiori-data'
powershell -ExecutionPolicy Bypass -File .\start.ps1 -DataDir 'D:\shiori-data' -Stop
```

源码运行无需 Node、Git 或前端构建。只准备环境使用 `-SetupOnly`；显式浏览器模式使用 `-Browser`。手动 Python 部署、HTTPS 反代、修复环境与实验性 Linux 运行见[源码部署指南](docs/SOURCE_DEPLOY.md)。核心包已迁为 `shiori`，旧 `qunyu` 导入和启动入口暂保留兼容，计划0.3.0移除，数据库文件名不变。无头部署安装 `requirements-server.txt`，Windows 桌面依赖单独放在 `requirements-desktop.txt`；Docker 与 HTTPS 见同一部署指南。

## 数据、密码与远程管理

Windows 默认数据在 **`%LOCALAPPDATA%\shiori\data`**，独立于程序目录；替换或移除程序时可保留。聊天、记忆、配置与运行日志使用这份数据；显式 `--data-dir` 时以实际指定路径为准。

专用密码文件是数据目录中的 **`security\webui-password.json`**：保存加盐 scrypt 校验值，Windows 外层再由当前账户 DPAPI 加密。忘记密码时，可在运行电脑的托盘菜单选择“重置 WebUI 密码”，或执行 `python -m shiori --reset-password`（使用同一数据目录）。也可完全退出 Shiori，只删除此文件，再从运行电脑打开并重新设密；聊天与记忆保留，旧登录失效。不要删除整个数据目录。换设备或 Windows 账户后，连接密钥可能需要重新填写。

默认只监听本机。需要其他设备访问时，先设置密码，再在“登录与远程管理”启用入口、保存并重启，默认要求通过自己的 HTTPS 域名登录；页面可生成 Caddy 配置。只有明确勾选“可信局域网允许明文HTTP”后，才可使用实际 IP 与端口的 HTTP 入口。仅本机免密不接受远程访问。普通 HTTP 不加密传输；跨不可信网络使用 HTTPS 代理或加密隧道，具体 Host 与代理要求见[部署说明](docs/SOURCE_DEPLOY.md#使用-https-反向代理)。不要分享启动链接中的本机初始化凭据。

升级前退出旧实例并保留完整数据副本，避免多个实例同时写一份数据。应用备份会脱敏，不包含有效密码与密钥；恢复后需重新配置连接。原始附件、蒸馏材料和电脑工作目录应另行备份。表情图片库在 `stickers/library.sqlite3`，请在表情包页单独导出；主应用备份不包含它。

## 在软件内选择版本与更新

右上角“版本与更新”可检查固定 GitHub 仓库、选择版本和查看说明。0.1.5 起支持后台校验程序文件、备份数据、直接替换程序、自动重启与启动失败回退，无需再操作安装器。适用于 Windows 安装版、便携版及非容器源码服务；源码本地修改会阻止覆盖，远程切换需宿主管理员授权。详见[更新指南](docs/UPDATES.md)。

默认只显示正式版。试用本次预发布时开启 **“显示测试版”**，检查并选择 `v0.2.1-beta`；稳定版仍为 0.2.0。测试版升级后不直接覆盖降级，回到历史版本需使用对应备份独立部署，详见更新指南。

0.1.6 及更早版本需从本仓库发行页手动下载，退出旧实例后覆盖安装或按原部署方式替换程序，沿用原数据目录；它们不能通过旧仓库的更新入口直接切换到本版。0.2.0 起支持从新的 Shiori 更新源切换版本。

## Shiori 更名兼容

全新安装默认使用系统用户目录的 `shiori/data`。若新目录为空、旧 `mikubot/data` 或 `qunyu/data` 已有数据，启动器直接沿用旧目录，不复制或合并。`--data-dir`、原密码、记忆、QQ 接入和管理员继续有效；数据库文件名 `qunyu.db` 保持兼容。新环境变量为 `SHIORI_DATA_DIR`，旧 `MIKUBOT_DATA_DIR`、`QUNYU_DATA_DIR` 仍可使用。

旧 `python -m mikubot`、`python -m qunyu` 和导入路径保留薄兼容层，统一转到 `shiori`，计划在 0.3.0 移除。安装器与更新器识别旧安装记录、旧发布文件名和旧服务名。历史发行说明、审计记录、第三方许可证及真实 GitHub 链接保留原始名称。默认初音未来人格不因软件更名而改变。

Docker 命名卷不会随产品目录自动迁移。已有容器部署升级前先确认原卷名，将 `SHIORI_DATA_VOLUME` 设为该卷的完整名称，再使用新 Compose；全新部署默认使用 `shiori-data`。不要让新旧容器同时写同一卷。
