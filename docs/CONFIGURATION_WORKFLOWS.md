# 配置与消息处理

本文对应mikubot 0.1.6的配置与消息流程。正式安装包的下载以GitHub实际公开发行资产为准。

## 从一个入口配置机器人

打开“机器人配置”：基本配置管理名称、人格、时间；“模型”管理供应商、对话和嵌入模型；“回复与记忆”管理消息防抖、回复长度、分段和检索；QQ 连接、电脑与管理员、人格库、表情包也在这里。

模型供应商的地址和密钥全局共用。新建连接、获取模型列表、选为默认模型，都在“机器人配置 → 模型”完成。读取目录不代表模型支持图片或工具，仍需按服务商说明设置能力并测试。对话图片跟随当前聊天模型，表情包识图可单独指定，嵌入模型仅用于检索。

“默认使用哪些模型”修改全局默认，不覆盖机器人配置或会话已经指定的模型；每个配置的编辑窗口仍可选择自己的聊天模型。高级模型分工显示各用途实际使用的型号，备用顺序也在这里设置。判断、记忆与整理未单独指定时，新配置自动继承全局对话模型；若旧版已完整填写基础默认连接，则保留该服务。人格蒸馏空用途继承全局对话模型，嵌入模型独立配置。停用或缺失的明确选择不会被悄悄替换。旧“模型供应商”入口自动打开新的模型页；系统设置保留登录、资源、预算等系统选项。

## 连续消息一起回复

在“机器人配置 → 回复与记忆 → 等你说完再回复”开启消息防抖，设置等待时间。默认关闭，开启后的初始值为3秒；持续收集最长等待默认30秒。普通等待可设0.1—60秒，最长收集可设1—300秒，且不得短于普通等待。

收到新消息会重新计时。例如第0、2、4秒分别发送一句话，三秒防抖会在约第7秒启动一次回复流程。QQ私聊和群聊均支持，群聊按发送者分别收集；每条原消息、图片、时间及来源仍单独保留。已经开始生成或发送的回复会继续完成，后续消息排入下一轮；停止、更正、暂停或撤权立即生效。

防抖在Planner之前完成，启用后不再叠加旧的短消息合并和群聊集中判断窗口。单轮最多8条，并受正文、图片和附件上限约束，达到条数上限会先处理一轮。电脑控制等明确命令不通过合并文本扩大授权。

记忆、待办和提醒命令按每条原消息单独处理，不把下一条普通聊天拼成命令参数。例如连续发送“记住：我喜欢咖啡”和“今天聊什么”，只会记住咖啡偏好，其余内容合成一次聊天回复。每条命令沿用自己的来源与发送时间；已成功的操作显示回执，后续模型失败不会自动重做。

全局设置可被机器人配置覆盖，机器人配置又可被单个会话覆盖。对应字段留空表示继承；不必逐个配置群聊。旧的独立会话选择保持兼容。

本地网页在发送前收集连续输入，显示待发送条数，允许“立即回复”和“取消收集”。取消会把内容放回输入框。等待期结束后一次提交，服务端分别保存原消息，再统一回复；它不承诺跨浏览器合并。刷新、关闭网页或退出登录会放弃尚未提交的收集内容。已提交的请求不会因为传输中断自动重发工具操作。电脑任务模式直接提交，不等待普通聊天防抖。

收集期内继续编辑的未发送草稿与本轮提交内容分别保存。提交成功不会清空下一轮草稿；失败或取消时把本轮内容还原供人工核对，界面刷新失败也不会自动重发。附件仍被草稿或下一轮收集引用时不会提前释放；这些草稿仅在当前页面内保存，不承诺刷新或关闭后的恢复。

## 核对现实时间

打开“机器人配置 → 基本配置 → 现实时间”，选择常用时区或填写IANA名称，保存后立即生效；也可使用浏览器时区。程序时钟预览来自运行mikubot的设备，而不是把浏览器时间冒充服务器时间。如果设备时钟有明显差异，页面提示核对，不自动修改操作系统时间。

平台发送时间、程序接收时间、历史录入时间和事件发生时间分别处理。今天说“昨天晚上看了电影”，不能因为今天录入就把电影发生时间写成今天；无法确定的事件时间保持未知。模型看历史时有简短时间标注，长时间排队、切换备用模型和工具续答会刷新应用提供的当前时钟。相对日期和提醒优先参考原消息时间，避免延迟到跨午夜后误解“昨天”。

同一条消息描述多个日期时，事件需要与对应的原文片段匹配；例如“今天去了海边，昨天看了电影”不会把两件事都标成今天。指代、改写或多个事件混在一起而无法唯一对应日期时，保留未知，不采用模型猜测的日期。

关闭现实时间感知后，不再主动向模型提供当前时钟；用户本身说出的日期、原始记录、提醒、日预算与统计继续保留。旧记录没有平台时间时使用明确标记的接收或录入时间，不伪造平台发送时间。

## 近期对话、昨天的事与长期记忆

在“资源与响应速度”设置“近期对话轮数”，默认24，范围1—100。程序从用户发言开始保留轮次；发送给对话模型的历史消息数与文字预算仍有独立上限。较长旧消息保留全文或按整轮省略，不再悄悄切掉尾部结论。

问“昨天聊了什么”“最近说到哪里”时，程序按原消息时间检索，并把用户与助手的旧话放在标明来源、时间和说话人的历史参考区。明确说“继续”“那后来呢”等时，也可从有界旧窗口补充上次话题片段，不因此默认开启付费摘要。片段不连续、资料过长或没有可靠来源时，应缩小时间范围或补充具体话题，不能把没有召回的部分当成已知。

这些片段会计入正常对话的输入Token。较大的近期窗口可能增加模型输入用量；需要更低开销时可调小轮数，原有Token与费用预算继续生效。

长对话摘要仍需全局与会话同时开启，调用计入预算。低内存配置的16条历史发送上限不会再阻止摘要触发；摘要无法装进当前输入时，会退回有效原文并报告本轮未压缩。超长摘要最多精简重试一次，失败原因保存在运行事件中。

首次自动记忆提取不再跳过一天以前的未处理原文；按32条有界批次和每日配额逐步整理，遗忘来源在分页前排除。已经整理完成的进度不自动倒带，来源撤回、用户隔离与审核规则继续生效。需要长期保存的内容仍可显式发送“记住：……”，并在记忆档案查看或纠正。

完整边界与逐项回归见[历史管线整改](HISTORY_PIPELINE_AUDIT.md)。

## 上传或生成插件

插件页默认提供“导入插件包”和“用聊天创建”。支持ZIP、tar.gz、tgz，自动识别外层文件夹并显示候选插件。清单、入口缺失或文件不兼容时直接说明原因，不把其他框架的任意Python文件当成mikubot插件执行。

规范包由`plugin.json`、`main.py`和`README.md`组成，允许辅助模块及资源。插件描述输入参数后，运行页自动生成表单；复杂对象仍可使用JSON。导入、替换或编辑先保存停用草稿，原修订可回退，也可导出规范ZIP。旧的单文件插件继续兼容。

本地聊天中描述目标，例如“创建一个按文件后缀整理目录的插件，参数是目标目录和是否预览，先保存草稿”。已经开启电脑能力和自动执行时，明确要求“创建并运行”可沿用现有授权；只要求创建不会自动运行。任务记录显示真实执行结果与产物，保存成功不代表运行成功。

已有插件可直接说“帮我修复 example_plugin 插件的重复输出”。模型先读取代码及修订信息，再保存新修订；原参数、说明和包内辅助文件在未指定修改时保留。如果期间插件已被其他操作改动，本次修改会被拒绝，需重新读取。修改后插件停用，核对后再启用；QQ消息不能使用此本地插件编辑入口。

上传扫描不执行Python、不安装依赖。运行复用现有电脑能力和沙箱设置，插件清单中的能力说明不授予额外权限。详细格式、资源路径、容量与安全边界见[插件开发与使用](PLUGINS.md)。

Python源码除了字数限制，还检查解析复杂度。单个候选过度嵌套或表达式过深时，会显示文件名与拆分建议，不影响同一压缩包内其他合法候选的安装。
