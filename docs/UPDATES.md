# GitHub 版本与更新

当前稳定版为 **0.2.0**，本次测试版为 **[0.2.1-beta](https://github.com/iownmmiku/Shiori/releases/tag/v0.2.1-beta)**。预发布需要在版本列表开启“显示测试版”才会显示，不替代最新稳定版；关闭此开关也不会将已经安装的测试版自动降级。以下为 0.2.0 起的通用更新流程。

更新源固定为 [iownmmiku/Shiori 的公开发行版](https://github.com/iownmmiku/Shiori/releases)（原仓库名 `mikubot` 现在是只含迁移说明的空占位仓库，不提供下载）。**0.1.6 及更早版本内置的更新地址仍是旧仓库名，仓库改名后无法在应用内检查或切换，请从发行页手动下载 0.2.0 安装包覆盖安装，数据会保留；0.2.0 起恢复应用内更新。**打开右上角“版本与更新”，检查版本、选中目标版本，点击“切换到 v…”即可后台获取程序文件、校验、备份、替换并重启。无需自己保存源码、解压或运行安装器。

程序必须获取新版本的程序文件；“无需下载安装包”指用户不必手动下载和重新安装，不是只改配置或版本号。

## 试用 0.2.1-beta

1. 退出旧实例，另存完整数据目录、原始材料、插件、表情图片与电脑工作目录。自动更新备份和脱敏导出不能代替这些独立副本。
2. 在 0.2.0 的“版本与更新”开启“显示测试版”，重新检查，选择 `v0.2.1-beta` 后查看说明并切换。也可从预发布页获取安装包、便携包或源码包，核对对应 SHA-256 后运行。
3. 希望与稳定版分别试用时，将便携包解压到另一目录，并指定独立数据目录，例如 `shiori.exe --data-dir "D:\shiori-beta-data"`。仅更换程序目录不会自动隔离默认数据。
4. 测试版加入角色日程、Chat 项目和事件记忆等数据结构。未声明与旧版的数据库降级兼容性；回退需用升级前的数据副本与对应程序独立部署，不直接让旧版读取修改后的测试数据。

不要让稳定实例与测试实例同时写同一份数据。测试版的详细变化与验证边界见[更新日志](../RELEASE_NOTES.md)和[测试报告](../TEST_REPORT.md)。

## 支持范围

- Windows x64 安装版与便携版：后台使用校验过的便携程序资产替换程序文件，保留数据目录和原快捷方式。
- Windows、Linux、macOS 源码运行：后台读取校验过的源码发行资产，替换发行清单中的程序文件。未提交修改或与上次更新清单不同的本地修改会阻止覆盖。初次切换需要源码目录可写。
- Linux 的 shiori.service：独立更新助手停服务、替换程序、启动服务，保持原监听端口。依赖变化时建立独立虚拟环境，成功后通过服务 drop-in 使用该环境，旧环境保留。
- Docker：通过更换镜像更新；容器内不直接替换宿主挂载代码或重建容器。

当前实现拒绝直接覆盖到低于当前版本的历史版本，因为历史版本没有声明数据库降级兼容性。历史版本仍可在高级选项中下载，配合对应的数据备份独立部署。相同版本修复重建可重新切换。

## 执行流程与数据保留

1. 从指定 Release 获取对应程序资产，显示进度。下载阶段可以取消，尚未更改程序。
2. 验证大小和 SHA-256，检查路径、磁盘空间、后台任务和模型请求。缺少可信校验值、程序被本地修改或有任务未结束时停止交接。
3. 暂停新的请求，等待原进程退出。独立助手备份配置、密码、聊天、记忆、知识、插件与其他数据文件；updates 自身不递归备份。
4. 按清单替换程序，写入持久替换日志，个人数据不混入程序替换集。源码依赖变化时先准备独立运行环境，准备失败不会覆盖旧程序。
5. 按原数据目录和固定端口重启。以本地健康接口核对版本与实例身份，检查窗口期间不接收新聊天或写入请求。
6. 启动失败时先安全停止新进程，再恢复旧程序、数据和服务启动配置。无法确认新进程已退出时停止自动覆盖，保留备份供恢复。

更新的进度与结果位于数据目录的 updates/install-result.json；每次切换的下载、程序备份和数据备份位于 updates/任务编号。成功后也保留备份，由用户确认稳定后再处理。备份会占用磁盘空间，不会随着程序卸载自动清理。

### 更新助手异常退出

新更新助手使用操作系统文件锁标识实际运行状态。重新启动时会核对助手及程序清单：尚未替换程序的中断会解除维护；已经完整替换且文件校验通过的版本恢复正常运行。部分替换或无法确认健康的状态会进入“恢复中断的更新”页面，不继续接收聊天。

点击“重新核验”可以检查修复后的状态。具备完整程序备份和数据 SHA-256 清单时，可选择“恢复更新前的版本并重启”，恢复到本次更新前的数据快照。恢复前再次核验所有备份，备份损坏时不自动覆盖当前文件；原备份继续保留。远程恢复沿用已有远程更新授权。

旧助手没有文件锁或备份完整性清单时，软件不会仅凭超时认定它已退出，也不会把存在备份目录当成备份完整。此类记录会明确提示人工核对与修复，避免永久显示没有进展的“正在更新”；请保留整个 updates 目录。

“版本与更新 → 管理更新占用”显示历史任务的程序文件、恢复备份及总占用。选定目录后再次确认才会清理；不会自动删除。当前任务、最近一次成功更新的恢复备份、未确认恢复结果的目录及缺少管理记录的旧目录受保护。预览后目录发生变化时必须重新读取，含符号链接或越界路径的目录拒绝清理。远程清理沿用宿主的远程更新授权，更新、下载和清理不能并行执行。

## 远程页面

默认只允许在运行电脑本地发起自动切换。本地“版本与更新”可开启“允许已登录管理员从远程页面切换版本”；服务器也可由宿主管理员将 settings.json 中 updates.allow_remote 设为 true 后重启。远程页面本身不能开启这个权限。

检查版本有 60 秒缓存，不会自动推送代码或自动选择新版本。后台下载只使用固定仓库的公开 Release、HTTPS 和指定 GitHub CDN。SHA-256 验证发行资产一致性，不等于独立代码签名。

## 旧版本升级

已经发布的旧客户端不会因为这份源码变更而自行获得新功能。安装本次包含直接替换更新器的版本后，后续版本切换才使用这里的新流程。旧安装器更新接口保留作为兼容入口，主界面优先使用直接切换。
