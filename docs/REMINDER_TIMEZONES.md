# 提醒的时区与夏令时

本文描述 Shiori 0.1.4 的提醒时区与重复日历规则。

新提醒默认采用“设置”中的 IANA 时区，例如 `Asia/Shanghai` 或 `America/New_York`。自然语言识别、明确年月日、提醒创建与改期、回复里的时间和模型提示词使用同一时区；QQ 静默窗口也按当前全局时区判断。

任务页可以为每个提醒指定 IANA 时区，日期输入框和列表都显示该提醒的当地时间。浏览器、Windows、服务器自身的时区不会暗中改变所填钟点。API 可传带偏移的 ISO 日期，或同时传入本地日期与 `timezone`；不带偏移也没有 `timezone` 的日期会被拒绝。

```json
{
  "title": "每天上午开会",
  "kind": "reminder",
  "due_at": "2027-10-30T09:00",
  "timezone": "America/New_York",
  "repeat": "daily"
}
```

程序保存 UTC `due_at`，同时保存 `timezone`、当地钟点 `wall_time` 和日历起点 `calendar_anchor`。每日和每周提醒按这份当地日历推进，跨夏令时仍维持上午 9 点，而不是固定增加 24 或 168 小时。

- 修改全局时区只影响新提醒和 QQ 静默判断，不会移动已经保存时区的提醒。
- 对已有提醒说“把喝水提醒改到明天上午十点”，采用该提醒已经保存的时区，并在回复中显示。需要换时区时可在任务页修改。
- 旧版本没有保存日历信息的提醒保留原 UTC 到期时间；首次修改或实际发送时，按当时全局时区补全日历快照。之后不随全局时区改变。旧记录原本的创建时区无法可靠推断，不伪造历史信息。
- 夏令时开始时不存在的当地钟点，创建或改期时明确拒绝，请选择有效时间。已经安排的每日/每周提醒若遇到不存在的钟点，跳过当次，保留原钟点等待下一天/周，并记录 `reminder_calendar_skip` 事件。
- 夏令时结束时重复出现的钟点，未指定偏移的当地日期采用第一次出现；周期提醒也只发送一次。API 若传入带偏移的 ISO 日期，则该次提醒按明确给定的瞬间执行。
- “一小时后”“五分钟后”按实际经过时长计算；“一天后”按当地日历保持钟点，跨夏令时时可能相隔 23 或 25 小时。
- 程序离线错过多次周期时，恢复后保守地发送一次，再推进至未来的下一个日历时点；不连续补发过期提醒。手动重试保留原来的钟点与每周星期，不把重试时刻变成新的周期。

提醒仍要求程序运行且相应通道在线。发出后未拿到确认的结果不会自动重发，需要人工核对；时区修复不改变这一行为。
