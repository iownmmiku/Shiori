# 本地插件

插件用于把重复操作保存成可复用的功能。插件页以“导入插件包”和“用聊天创建”为主要入口；旧版手动编写的单文件插件继续可用。

## 安装别人提供的插件

1. 打开“插件”，点击“导入插件包”，选择 `.zip`、`.tar.gz` 或 `.tgz` 文件。
2. 程序自动识别 `plugin.json` 和外层文件夹。包含多个插件时，选择要安装的一项；校验失败会指出文件和原因。
3. 同名更新需勾选“替换并保留旧修订”。安装和替换都先保存为停用草稿，不执行代码。
4. 查看用途、入口与运行要求，启用后点击“运行”，填写自动生成的参数表单。运行结果在“后台任务”查看。

上传最多8MB，解包后总大小最多16MB，单个文件最多2MB；文件和目录合计最多128项，目录深度最多10层。TAR 另限制含扩展头、元数据和填充的总解压大小，防止元数据绕过文件上限。拒绝路径穿越、绝对路径、Windows 保留名与非法字符、链接、特殊文件、加密包、重复路径、大小写冲突，并在读取前限制解压大小。当前不支持 RAR、7z、AstrBot 插件格式或插件市场。

校验只解析清单和 Python 语法，不导入或执行插件。入口与辅助源码都限制解析树的深度和节点数；过长的运算链或过深的嵌套会显示对应文件与拆分建议，不会使整个导入接口报错。多候选包中，其他校验正常的插件仍可选择安装。语法正确不代表插件能够正确完成任务；第三方插件应先用少量测试数据运行。依赖声明会显示提醒，不自动执行 `pip install`。

## 用本地聊天创建

先连接支持工具调用的对话模型、开启电脑能力，再点击“用聊天创建”，补充目标。例如：

> 帮我创建一个插件，把输入文本中的重复行去掉。参数叫 text，请提供使用说明，先保存为草稿。

模型使用 `create_plugin` 保存插件、参数定义和说明。进入插件页即可查看、启用、运行，或导出标准 ZIP。参数表单支持文本、数字、开关、枚举；对象和数组使用 JSON 编辑。复杂 schema 仍可使用完整 JSON 输入。

已经开启电脑自动执行时，明确说“帮我创建一个去重插件并运行，输入是……”可以连续创建、启用和运行，不增加逐步确认。仅说创建、供以后使用或明确“不用运行”时仍保存停用草稿。创建回执不代表运行成功，实际结果以后台任务为准。需要修改时可以继续在本地聊天中说明问题；每次保存修改会停用当前插件，避免旧授权继续执行新代码。

例如：“帮我修复 deduplicate_plugin 插件，保留空行，其他行为不变。”模型可用 `list_plugins` 确认 ID，再用 `get_plugin` 读取入口代码、参数定义和使用说明。长内容分页返回，需按 `next_offset` 继续读取，不能把部分代码当成完整文件。随后调用 `update_plugin` 保存新修订；未提供的新名称、参数、说明以及包内辅助文件均继续保留。

修改必须提交读取所得的修订号和摘要；若其他窗口已编辑、启停或替换该插件，本次修改会被拒绝，现有内容不变，需要重新读取。`create_plugin` 不会覆盖已有 ID，避免通过“重新创建”绕过修订核对。修改不会自动运行，保存后在插件页核对并启用；仅询问“如何修复插件”不会授予修改权限。电脑能力与本地管理员限制继续适用，QQ 聊天不能使用这些入口。

## 标准插件包

```text
my_plugin/
├─ plugin.json
├─ main.py
├─ README.md
├─ helper.py          # 可选辅助模块
└─ assets/            # 可选资源
   └─ example.txt
```

允许任意安全的外层文件夹。清单结构版本 `schema_version` 固定为1，与 mikubot 软件版本及内部存储版本无关。

```json
{
  "schema_version": 1,
  "id": "deduplicate_plugin",
  "name": "文本去重",
  "version": "1.0.0",
  "description": "保留原顺序，去掉文本中的重复行",
  "entrypoint": "main.py",
  "input_schema": {
    "type": "object",
    "properties": {
      "text": {"type": "string", "title": "待处理文本"}
    },
    "required": ["text"],
    "additionalProperties": false
  }
}
```

ID 使用2—48位小写字母、数字、下划线，以字母开头。`name`、`description`、`version` 必填。入口默认 `main.py`，须同步定义 `run(input)` 并返回可 JSON 序列化的结果；入口和每个辅助 Python 文件均最多10000字，较大的逻辑请拆分为多个辅助模块。资源文件仍支持单文件2MB上限。

```python
def run(input):
    lines = input["text"].splitlines()
    return {"text": "\n".join(dict.fromkeys(lines))}
```

可选 `capabilities`、`dependencies` 是字符串列表，`requires_python` 是运行要求说明；它们不授予权限、不改变系统 Python，也不安装依赖。只使用当前运行环境已具备的模块。`README.md` 建议提供，不存在时会在安装时补充基础说明。输入定义使用有界的 object JSON Schema，不支持 `$ref`、动态引用或正则规则。未声明参数时，兼容通用 JSON 对象输入。

代码可以导入包内辅助模块；包根目录和入口所在目录均加入子进程的模块查找路径，因此 `src/main.py` 可以直接导入同目录的 `helper.py`。工作目录始终是任务工作区，不会切换到插件代码目录；相对路径写入的产物保存在工作区。读取随包资源时使用 `Path(__file__).parent / 'assets/文件名'`；不要使用 `open('assets/文件名')` 假定工作目录就是包目录，也不要依赖用户安装路径。运行参数由系统以 JSON 传入，不要将输入拼接成可执行代码。

## 修改、回退与数据位置

“查看 / 编辑”支持修改入口和参数定义，其他辅助文件与资源继续保留；修改更多文件时，导出 ZIP 后编辑并重新导入。每次替换或修改都保存旧修订；“回退旧修订”恢复上一份不同内容的代码包，恢复后仍停用。安装通过不可变文件目录和单个原子元数据替换提交，提交失败保留之前的插件。

旧单文件记录继续保存在 `data/plugins/<ID>.json`。规范包使用同一元数据文件，文件实体在 `data/plugins/.packages/`，历史在 `data/plugins/.history/`。导出 ZIP 是可携带的规范格式，不包含启用状态、运行结果或管理员权限。备份时应保存整个 `plugins/` 数据目录；删除插件入口不会清理已有任务产物或历史内容。

## 权限、文件与停止

服务进程不 import 插件代码。运行复用电脑任务的子进程、运行环境、时限、输出上限、审批与停止机制；不在 Web 服务进程执行。只有认证的本地管理台管理员能在 `web:` 聊天中生成或运行插件，QQ 管理员不能调用此入口。电脑能力关闭、会话暂停、工具关闭或插件修订变化都会阻止任务继续；重启不自动重放插件任务。

任务目录为电脑工作目录下的 `plugins/<插件ID>`。规范包文件只在获准运行的子进程内写入该任务目录，再加载入口。能力声明不是权限授权，自动执行仍受既有管理员和电脑配置约束。

**Docker 沙箱隔离主机系统，不保护工作目录内的文件；/workspace 是可写映射，脚本可在其中增删文件。**插件使用自身任务目录。缺少指定 Docker 环境时停止，不退回宿主。本机模式以当前系统账户权限运行，专用目录本身不构成沙箱。

停止任务不会撤销已经发生的文件修改或外部效果。任务进度、真实输出和失败原因可在“后台任务”与运行日志查看。
