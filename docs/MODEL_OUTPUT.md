# 回复内容与模型消息边界（0.1.4）

本文描述0.1.4。模型自行分段从0.1.3提供；本版增加可选内容上限、括号处理、均衡合并和原文查看，默认不限制长度、不删除括号内容。

默认 `output.mode: model`。自然对话生成前，提示词要求模型自行决定独立消息的边界，用一个空行分隔；单换行属于同一条内的排版。可以只有几个字、一条一句，也可以一条包含多句，不规定必须发几条。不另发一次模型请求重新分段，不按标点或目标字数猜边界。

例如模型直接生成：

```text
嗯，今天还不错。

刚刚听完一首喜欢的歌。感觉心情也轻松了一点。
这一行仍属于同一条消息。

你呢？
```

发送为三条；中间这一条含两句话与一个单换行，保持完整。模型没有空行时整条发送，程序不会补切。只有空白的段不会发送。代码围栏内部的空行、完整JSON对象/数组不会被当作独立消息分隔。

新回复在原聊天正文之外保存 `metadata.reply_parts`，API同时返回 `reply_parts`。本地聊天使用这些已保存的边界显示消息；旧记录保持原样，不按新规则重切。UI只显示与原正文一致的段落，用户消息不使用此元数据。

## 设置入口与内容限制

实际入口为 **机器人配置 → 回复与记忆 → 回复内容与消息分段**。本会话设置中的“单独设置本会话输出”可以覆盖，关闭则继承全局；部分字段未指定时也继承全局。内容规则独立于分段开关和旧版长度参数。

| 设置 | 配置字段 | 默认值与范围 |
| --- | --- | --- |
| 整轮回复字符上限 | `output.reply_max_chars` | `0`表示不限制；可设0—20000整数 |
| 单条消息字符上限 | `output.message_max_chars` | `0`表示不限制；可设0—4000整数 |
| 删除括号及其中内容 | `output.remove_parentheses` | 默认`false`；开启后移除正文中的中文/英文圆括号及其中内容 |

中文、英文、标点和空格均按字符计数，换行不计入。整轮是这一轮各条AI正文的合计；单条是每条模型消息的上限。优先通过生成提示让AI自行简洁表达、自行在完整意思后分段；不为缩短或重排额外请求模型。

明确开启上限后，超出正文会缩短展示，聊天中可展开原始回复。完整代码、链接、JSON等受保护内容不能截成残片；无法在上限内完整放入时显示查看原文提示。删除括号时也保护这些内容，未闭合或不匹配的括号保持原样。只处理AI回复正文，不移除系统命令说明、工具执行回执或确认凭据。

例如只限制总长、不限制单条，并删除括号内容：

```json
{"output":{"reply_max_chars":500,"message_max_chars":0,"remove_parentheses":true}}
```

原始生成正文保存在消息的`metadata.original_reply`，调整说明在`metadata.output_adjustment`；展示正文与`reply_parts`使用调整后的版本。旧记录不回溯改写，原始回复的保留也不代表被过滤或缩短的正文仍会发送到QQ。

## 自然分段与消息条数

默认选择“模型自然分段”；已有设置没有`mode`时也使用此默认。可独立调整发送间隔、连续消息条数和平台保护：

```json
{"output":{"enabled":true,"mode":"model","interval_ms":600,"max_parts":8,"platform_max_chars":1800}}
```

`max_parts`是防刷屏上限，不强制分满。模型产生的消息超过上限时，程序只在已生成的边界上均衡合并相邻段落，保留顺序；不把全部长尾内容堆成最后一条，也不把一个超长模型段落重新按句子切开。关闭分段后保持一条，内容上限和平台保护仍有效。

`target_chars`、`max_chars`仅在主动选择兼容模式`mode: length`时生效；它们不是整轮或单条内容上限。正常模式不使用这两个旧参数，界面折叠展示。

## 增量预览

未开启内容限制时，本地网页可逐步预览文本。开启任一字符上限或删除括号内容时，预览等待完整且可安全处理的模型段落，最后一段等待最终结果；因此可能稍后才出现，但不会先闪现随后被删除的括号内容或半截受保护片段。最终结果会替换草稿，工具调用、取消或失败可清空草稿；预览不是执行成功的回执。

## 发送边界

消息超过通道长度保护上限时，仍必须进行传输切分；完整链接、代码或字符不能完整容纳时停止发送，原文留在本地。这是异常长度保护，不承担日常聊天分段。每条仍检查权限、来源和请求是否有效；未知或失败回执停止后续条，不盲目重发。平台明确拒收（连接器回复 `rejected: result=…`）说明这一条没有送达：限速拒收时记下群的每分钟上限，等窗口空出后重发一次；其他拒收不重发，发送记录把它和后续段落标为未发送，可确认后补发。已知上限的群在剩余额度不足时，把一轮回复剩下的分段合成一条。官方QQ的被动回复序号按实际发送条数连续编号，后续表情包也继续使用实际序号。

模型是否遵守排版规则取决于模型能力；没有开启字数上限时优先保留完整回复，开启后按内容限制缩短展示并保留原文，不额外付费重写。测试使用模型与QQ协议替身，不代表真实QQ风控、付费模型分段风格已验收。参考项目的公开生成/后处理扩展机制可见[MaiBot Hook文档](https://docs.mai-mai.org/plugin/hooks)；本实现直接要求首轮生成确定边界。
