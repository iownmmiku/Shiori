# 消费核对的能力边界

核查日期：2026-10-21。本文对应 Shiori 0.1.4；没有使用用户密钥，也没有向收费模型发起请求。下表核实的是官方公开接口文档，未完成供应商账号实测。

## 当前可以怎样核对

在运行 Shiori 的电脑本机打开“数据统计 → 管理待核实消费”，核实供应商记录后，填写实际用量与费用，或确认未计费，并记录依据。软件保留原估算与审计信息，同一核对操作重复提交不会重复入账。请求尝试次数继续保留。远程登录可以查看，不能通过此接口核销。

“服务返回用量”表示收到响应里的 Token 数，不表示费用已经由供应商账单核实。当前金额根据所配置的输入、输出单价计算，缓存折扣、工具费用、币种、套餐等可能导致它与最终账单不同。未配置价格时，金额为0也不能证明免费。

本地 `request_id` 是 Shiori 生成的关联标识，不是供应商的请求编号。目前没有保存可用于按次查询的供应商 generation id，也没有自动账单查询适配器。超时记录不能直接拿这个本地标识到供应商查询，更不能因查询不到就清零。

## 官方接口核查

| 服务 | 已核实的公开能力 | 能否直接核销某一条超时记录 |
| --- | --- | --- |
| OpenAI | Usage/Costs 按时间桶、项目、模型等汇总；不是按任意 `request_id` 查询单次账单。 | 不能据此把某一条未知记录认定为0或某个精确金额。见[官方 Usage API](https://platform.openai.com/docs/api-reference/usage)。 |
| Anthropic | 组织 Usage/Cost 报表需要管理员权限，返回时间桶内聚合数据。 | 聚合报表可用于总额比对，不能直接定位某一条中断请求。见[官方 Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)。 |
| DeepSeek | 公开余额接口返回账户总余额、赠金与充值余额。 | 余额会受其他请求、充值和赠金影响，不能用于单次核销。见[官方余额接口](https://api-docs.deepseek.com/api/get-user-balance/)。 |
| SiliconFlow | 公开 `GET /user/info` 返回账户信息与余额。 | 不能把余额差额直接归因于某一请求。本次未在公开规范找到可按请求编号查询单次消费的接口。见[官方 OpenAPI 规范](https://github.com/siliconflow/siliconcloud/blob/main/openapi.yaml)。 |
| OpenRouter | `GET /api/v1/generation?id=…` 按供应商 generation id 返回 Token 与 `total_cost` 等元数据。 | 可作为专门适配器的候选，但必须先保存真正的 generation id 并验证响应归属；它不是本地 UUID。见[官方 generation 查询](https://openrouter.ai/docs/api/api-reference/generations/get-generation)。当前未实现。 |
| 任意 OpenAI 兼容地址、反向代理 | 对话协议兼容不代表兼容账单接口。 | 必须单独核实实际收费方提供的接口与标识，不能根据模型名套用原厂账单。 |

“未找到”仅表示本次对公开规范的核查结果，不代表供应商没有私有、企业或后续新增接口。

## 后续自动核对的最小可行范围

优先实现明确选择供应商的只读适配器，例如具有真实 generation id 的 OpenRouter 对话请求；不根据地址中的关键词或模型名猜测收费方。先取得并展示“核对建议”，保留当前本机管理员确认流程，再讨论自动写账。

适配器至少需要保存供应商编号、供应商返回的 generation id、请求时间、模型、账单币种，以及用于确认请求归属的非敏感元数据。查询必须使用原供应商的受控地址、独立超时、有界重试和最小必要凭证；不得向任意响应给出的 URL 转发密钥。

缺少远端编号、断在首个响应之前、404、结算尚未完成、权限不足、供应商配置已经更换，均应保留“待核实”。聚合报表、余额和本地超时时长不能当作“未计费”证据。不能为补一条账单重新执行原模型请求。

若要自动落账，还须验证非负有限数值、币种一致、记录归属与结算完成状态，保留原估算、查询来源和核对标识，并在事务里确保幂等。没有这些条件时，继续使用人工核对是当前明确支持的方式。
