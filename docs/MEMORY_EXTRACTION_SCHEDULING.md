# 自动记忆整理的节奏与进度

自动记忆整理会调用模型，与聊天时读取已有记忆分开计算。每日上限设为60时，自动任务之间约间隔24分钟；实际间隔按配置时区当天的长度计算，夏令时切换日也遵守该日额度。空闲时间不会积攒成一次性突发整理。

当天消耗和最近一次整理时间持久保存，重启、更新和跨日都不会抹掉已经发生的消费。0表示关闭自动整理，不表示无限。手动整理可以跳过自动节奏等待，但仍消耗同一每日额度，不能绕过已用完的上限。

## 近期对话与历史积压

自动调度优先最近24小时内的有效原始消息，通常每3轮近期任务后保留1轮处理历史积压；某类没有可处理内容时可使用另一类。不同成员分别取材，不把他人消息当作当前用户授权。

近期消息可以先于旧积压被整理。系统保存已成功处理的确切消息ID，历史游标只越过连续已处理的部分，避免为了照顾近期内容而跳过未处理历史。成功返回空数组表示没有值得保存的内容，会记录该批已处理；它不代表新增了记忆。

失败、残缺结果、无效候选格式以及来源或权限变化不会被当成成功整理，也不会推进未验证的进度。失败退避从5分钟逐步增加，最长1小时，实时观察和后台轮询使用同一规则；成功处理后清除失败计数。自动全局节奏仍同时生效。

## 为什么暂时没有新增

- 先确认会话的自动记忆开关、每日额度以及模型路由。
- 额度已用完时，原始消息和已有进度保留，等配置时区的下一日恢复；不自动提高额度或清零账本。
- 未到下一自动时段、消息尚在等待空闲、错误退避期间，都可能暂时没有模型调用。
- 合法空结果、待审核候选和已生效记忆应分别查看；不能只用记忆总数判断整理是否成功。

本轮回归覆盖重启、并发声明配额、当前日已耗尽、跨日间隔、23/25小时日历、手动共享额度、失败退避、近期优先、移动时间窗口和历史补齐。对真实模型质量和收费仍以所选供应商为准。
