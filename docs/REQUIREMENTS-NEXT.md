## 1. 名称、别名与三种触发信号

用户要求：设置中能配置机器人名称与别名，提及名称也能回应；名字、@、回复分别有开关。

建议规格：

- 区分产品品牌名和实例的机器人称呼。机器人称呼影响自我介绍、人格提示、名称识别；修改称呼不要求重装或改产品名。
- 设置全局名称和多个别名；会话可继承，按需覆盖。界面展示当前实际生效的名称。
- 独立提供“响应@”“响应回复机器人”“响应名称／别名”三个开关。回复他人不视为回复机器人。
- 开关决定是否把该信号作为定向触发依据，不把三者合并为一个不可区分的explicit标志。群主动参与另有开关。
- 名称出现在引用、转发、第三人叙述中，仅是候选线索；Planner开启时结合上下文判断是不是在叫机器人。
- 关掉某种定向触发，并不自动关闭整个群的主动参与；若希望只按启用的定向信号回答，可关闭主动参与。

验收：只开名称时叫有效别名可以进入回应流程；关名称且关主动参与时不会因别名出现而接话；@与回复开关互不影响；角色自述使用配置名称。

## 2. 无wait的语义Planner

用户要求：借鉴MaiBot的Planner，先判断该说什么、是不是对自己说的、该不该回复；不学习wait；按会话控制开启，能设置某个私聊必回复。

建议规格：

- Planner负责判断和规划，Replyer负责最终措辞。Planner输出仅有“回复／本轮不回复”，不包含wait行动或等待后再自行重判的循环。
- 规划结果包含：目标消息、回复对象、是否对机器人说话、是否回复、简短理由、回复意图、必要资料／工具需求。理由是可查看的判断说明，不保存模型内部思考过程。
- 回复意图例如回答问题、安慰、澄清、补充信息、接梗或执行明确请求。不可只输出一个是否回复的布尔值。
- 保留全局默认和单会话覆盖。Planner关闭时直接按已启用触发规则和会话回复策略进入Replyer，不额外调用Planner模型。
- 单独提供“每条有效消息回复”的会话策略。指定私聊可设“Planner关闭＋每条回复”；Planner开启时，必回复策略也不能被其静默否决。
- 必回复仍遵守用户设置的总暂停、允许列表、工具权限和可用预算；失败应给清楚的处理结果，不能假装已经回答或办完。
- 一轮判定不回复就结束，收到新消息再重新判断。必要的网络等待、发送限速不属于Planner行动。连续短消息合并作为独立设置，不以wait行动实现。
- 定向触发也要区分“不用回答／停止”等明确取消意图。关闭Planner不能让取消消息变成继续执行旧操作的授权。

验收：群中询问他人不会因出现机器人名字就机械作答；指定私聊关闭Planner后仍逐条回复且无Planner调用；规划可查看目标和意图；不产生wait状态或定时重判任务。

官方参考：[MaiBot模型配置](https://docs.mai-mai.org/manual/configuration/model-config)将Planner与Replyer分工。这里借鉴其决策与措辞分离，行动集合按用户要求独立设计，不照搬完整循环。

## 3. 更有判断力的群聊主动参与

用户要求：主动群聊比单纯读空气更聪明，不依赖随机概率回复。

建议规格：

- 统一由语义Planner判断当前话题、交谈对象、未解决问题、机器人是否有相关知识、参与能提供什么价值，以及此时插话是否合适。
- 识别他人已给出答案、话题已经结束、成员正在互相交流、机器人已重复回答等情况，减少无贡献插话。
- 对求助、明显开放讨论、与人格兴趣相关且能补充实质信息的场景，可以主动参与；不是只有带问号的句子才有资格进入判断。
- 活跃度控制参与范围、冷却与发言上限；不把活跃度换算成随机抽签概率，也不让“积极”代表每条都答。
- 给出可查看的参与理由与目标，输出内容与规划意图一致。无明确贡献时本轮不回复。
- 区分“参与已有话题”和“无人说话时主动开启话题”。用户明确要求前者；后者另列可选能力，不默认开启。

现状备注：0.4已经没有随机抽签回复，主要不足是规则与有限语义门控较浅。本需求重点是扩大语义判断的内容与场景。

验收：同一条消息在不同上下文中可作不同决定；有人已完整解答时不重复；没有直接提及但能补充有效信息时可以接话；调整活跃度不会引入随机发言机制。

## 4. 定期探索与专属人格知识库

用户要求：机器人定期寻找网上热梗，或者主动了解人格感兴趣的内容，例如喜欢番剧的人格了解近期新番，并放到专属人格知识库。

建议规格：

- 人格配置兴趣主题、排除主题与探索频率；支持总开关、单人格开关、手动探索、暂停、下次计划与运行记录。
- 流程为选题→公开搜索／阅读→核对来源和时间→去重整理→写入人格知识库→以后按话题检索。不能用模型猜测代替联网。
- 知识保存来源链接、采集时间、适用时间、主题和人格归属；新番排期等有时效的信息需要更新／过期标记。
- 热梗保留含义、常见语境和出处。不把网络梗直接写成“本群黑话”，也不凭热度强行使用。
- 公共资料可自动整理入库；来源弱、矛盾或解释不确定的内容作为候选。用户可以修改、删除、禁止再次学习某来源。
- 人格兴趣可以指导选题，但不能借探索读取其他隔离聊天的私人资料。人格知识与“用户说过什么”的聊天记忆分开保存。
- 配置请求数／Token／网络阅读上限与失败退避；电脑未运行时不执行，恢复后避免积压任务集中触发。
- 默认仅探索和积累知识，不把每次探索结果自动推送群聊。是否主动分享及分享范围留作单独偏好。
- 这是项目内部拟议功能，本次不创建实际定时任务或开启任何自动联网。

验收：番剧兴趣人格能得到带来源及采集日期的真实新番资料；重复探索去重并更新；无法联网时如实失败；资料只能在获得相应人格知识权限的会话召回。

## 5. 可选择隔离或共享的聊天空间

用户要求：不同聊天可选择是否隔离；隔离后记忆不互通。

建议规格：

- 当前默认全部按会话隔离。后续增加“独立空间／加入指定共享空间”，并在界面列清共享对象，避免一个含糊的全局共享开关。
- 独立空间不读取其他聊天的原文、事实、偏好、事件、摘要、黑话、表达或私有派生资料。语义索引和历史回复来源也受同一边界约束。
- 非隔离聊天只有加入同一共享空间才互通；来源仍保留原会话和真实用户身份，不能把两个同名成员当作同一个人。
- 建议默认共享经确认的长期记忆，原始聊天、群语言、任务／工具回执是否共享另设明确范围；这些范围尚待后续确定。
- 私聊资料向群聊开放建议单独授权，不能仅因共用人格而自动公开。跨平台用户身份需要明确绑定，不能按昵称猜测。
- 切换为隔离后立即停止跨空间检索，已有摘要／上下文／缓存须同步失效，避免旧回复带回共享内容。
- 新加入共享空间不自动合并历史私聊资料；历史合并应独立显示范围、可审阅并可撤销。删除／更正应影响共享范围内的派生引用。
- 公共网络人格知识可以另行选择共享；从隔离聊天衍生的资料不能通过人格知识库绕过隔离。

验收：独立A无法通过直接检索、摘要、语义检索或历史复述取得B资料；同共享空间可访问已授权记忆；退出共享立即停止召回；不同平台同名用户不混同。

## 6. 自然长度与按长度分段输出

用户要求：分段数量由长度决定，不要求固定几句话；可以只说几个字或一句，也可以连续多句。

建议规格：

- 分开“该说多长”和“长文本怎样发送”。Replyer按语境与人格决定内容量，不为分段而凑字、凑句。
- 短内容直接一条，例如“来了”“嗯嗯”或一句完整回答；多个短句也可在同一条中发送。
- 只有内容较长时，发送端按目标长度并兼顾自然停顿拆分。目标长度是可调的软范围，不是固定句数或固定消息数。
- 保留链接、代码块、引用、列表及必要语义整体，不按每个标点强制切段，也不切断Unicode字符。
- 群聊和私聊可分别配置分段长度、是否分段和段间间隔；具体默认数值等后续整合时确定。
- 消息数上限仅用于控制刷屏，不要求每次达到上限。长内容可以改用较长消息，不能为了上限丢掉后半段。
- 一次逻辑回复的各段关联同一请求；引用链识别所有已发段。中途出现新请求／停止时取消尚未发送段，已送达段保留真实状态。
- 部分发送失败不自动重发整组，避免重复；官方QQ接入遵守实际发送权限与限制。

验收：短回复不拆分；同一长度的不同内容可因自然边界拆成不同数量；较长回复可多段；链接／代码不被粗暴切断；中途打断不继续刷后续段。
