# 0.1.2 上手、聊天、记忆与表情包整改

日期：2026-10-19–20。以下改动整合到 **0.1.2**，随源码、Windows安装版及便携版发布；完整发布验收见[测试报告](../TEST_REPORT.md)。

## 本轮变化

1. 快速入门和通用弹窗固定底部操作区，只滚动内容，小窗口和浏览器缩放后仍可保存。Windows 安装器也固定底部按钮，正文可滚动。
2. 安装器选择父目录后自动追加 `shiori`；已选择同名文件夹或带安装记录的旧安装位置时直接沿用，避免重复嵌套。命令行 `--target` 的精确路径语义保留。
3. 初音未来和其他人格均可删除。使用它的配置和聊天自动选择其余人格；人格库为空时使用普通助手，重启不会重新添加初音未来。记忆、词典与聊天记录保留。
4. 每页右上角显示当前版本与“版本与更新”，点击即可查看、检查和选择 GitHub 版本。打开入口只读本地状态，点击检查后才访问 GitHub。
5. “机器人配置”集中为基本配置、回复与记忆、QQ 连接、电脑与管理员、人格库、表情包六类。系统设置保留登录与远程管理、预算、备份等功能。
6. 新配置默认黑名单：接收未被屏蔽的群和私聊，无需逐个填写账号。旧配置保留白名单，需明确切换才扩大接收范围。OneBot 与官方机器人分别保存规则。
7. 真实连接收到聊天后自动收集会话。被接收规则拦截时只收集会话标识，不存消息正文。新聊天继承默认配置；旧聊天保留原设置，点“恢复默认”即可迁入。列表可搜索、屏蔽/允许、查看记录和单独配置。配置继承不等于记忆互通。
8. 按长度选择自然停顿，优先完整句子和收尾引号；普通长句可超过目标长度，但仍受发送长度上限约束。代码、链接和 Unicode 字符保持完整。发送前丢弃空段并去掉首尾空行，代码内部缩进和空行保留。未确认送达后停止剩余段，不盲目重发；日志记录连接器错误码或脱敏堆栈。
9. 快速入门不再要求先填白名单。本机自动配对在连接器配置成功后才生成/保存连接令牌并启用，避免首次没有令牌时提前启用失败；打开配对表单也不清空原有正向连接地址。手动连接参数和屏蔽列表收进可选区域。

## 建议使用顺序

先在“机器人配置 → 基本配置”编辑默认人格、模型和群聊方式。未单独设置的私聊与本地聊天默认每条回应，群聊默认适时回应；默认配置内可以改变私聊策略。

然后在“QQ 连接”选择接入方式，本机 NapCat / SnowLuma 使用自动配对。收到一条消息后，在“群与会话”查看自动收集的聊天；通常不用再配置，特殊聊天才覆盖设置。旧白名单用户可继续使用原规则，或明确切换黑名单。

“恢复默认”清除该聊天的人格、模型、回复、学习、Planner 与输出覆盖；聊天名称、启用状态、聊天记录、记忆和记忆空间保留。共享空间是否互通仍受可见范围和当前接收权限约束。

## 验证边界

测试均使用隔离数据、本地模型或协议替身；没有连接真实 QQ、调用用户模型密钥或修改用户数据。小窗口页面和 Windows 安装器布局另行验收。0.1.2发行包包含这些改动。完整结果补充在 [测试报告](../TEST_REPORT.md)。

## 弹窗提示与大量记忆（同日追加）

弹窗打开时，通知区域会进入原生 `dialog` 的顶层，显示在弹窗顶部；关闭或按 Escape 后回到页面通知区域。已有提示也一起迁移，错误文字不会被背景遮罩虚化。960×600 窗口实际验证了错误提示清晰可见、正文仍能滚动、保存按钮仍在视口内。

记忆档案改为每页 50 条，搜索和筛选在全库执行并重置页码。“关系与整理”点击后才读取数据，关联备选每次最多 200 条；关联弹窗的两个端点可分别搜索较早的记忆，每次最多 50 条，不必把全部记忆加载到浏览器。

召回复用有容量预算的分词缓存（估算上限 64 MiB），每次重新评分。权限检查在单次投影中按来源会话复用，最终候选和历史消息只读取它们引用的记忆及依赖。来源撤销与诊断计数由 SQL 读取需要的字段，不反复解码完整正文。Planner 的本地预览也复用缓存并进入有并发上限的后台检索队列；该预览不调用向量服务。

缓存不保存授权或最终答案。删除、改写、归档、关闭聊天、撤销共享与来源变化仍在当前投影和返回前校验；共享空间的关系召回继续生效。数据库结构与旧备份格式不变。不带 `limit` 的旧记忆列表 API 继续返回列表；界面使用带 `limit/offset` 的分页响应。

同机 8000 条合成记忆、固定本地回复替身的测量：修复前为单次，修复后为三次独立启动的中位数；检索返回 8 条。此结果不包含真实网络、付费模型生成或向量 API 延迟。

| 项目 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 首次召回（无分词缓存） | 2053 ms | 1454 ms |
| 后续不同查询召回 | 2086 ms | 383 ms |
| 测试回复流程（固定本地模型） | 6541 ms | 761 ms |

首次召回仍需分词和扫描候选；缓存超过预算时会淘汰旧项。当前词法排序仍随可见记忆量增长，不能据此承诺任意规模或真实模型的固定响应时间。最新回归结果见测试报告。

## 2026-10-20 表情包与群聊集中判断

新增“机器人配置 → 表情包”：收集和发送默认开启，两个概率均为0.1。群图片经有上限的后台识图后保存原图、语义、分类和标签；普通图片不入库，不明确的条目归入待标注。语义、分类、标签、是否明确、是否启用与是否共享均可手动调整。库按页读取，每页50张，支持全库语义搜索与分类筛选。

每次文字回复确认送达后最多尝试一张表情。概率命中后仍需模型确认当前语境合适，模糊条目、无意义描述、不合适的候选均不发送。候选发送给匹配模型前、模型返回后、平台发出前均重新核对来源与条目版本。默认不跨群；共享还须显式开启、处于同一共享记忆空间且两个群权限仍有效。

NapCat / SnowLuma 使用 OneBot 图片段及 echo 回执；QQ 官方机器人使用已安装 SDK 的签名 HTTP 客户端上传本地图片，再发送富媒体消息，序号续接文字的实际发送段数，动画在该通道转换为静态首帧。官方上传期间发生请求替换或权限撤销时不再发出。参考腾讯维护的 [媒体接口说明](https://github.com/tencent-connect/qqbot-nodejs/blob/main/USAGE.md)，实机平台权限与配额仍需用户环境验收。

图片下载拒绝本机/内网、限制重定向和体积，并验证图片格式与像素数；识图队列最多4项、串行处理。默认每天最多30次识图、1000张图片，图片总大小上限128MB。独立库在数据目录 `stickers/library.sqlite3`，界面提供单独备份；应用主备份的清单提示不包含表情图片。主数据库结构和备份格式保持不变。

普通群消息先集中收集，再进行一次 Planner 判断，默认1500毫秒或4条提前触发。@、引用回复、点名和私聊及时处理；原有同请求合并、冷却与判断间隔保留。上下文包含批内原始观察，目标是最新发送人，不把多人的指令拼为同一个执行请求。关闭、撤销或出现直接请求时会丢弃等待中的旧批次。

回归和浏览器验收只使用隔离图片、模型替身及本地协议回执。没有使用用户 QQ 账号或付费模型；不能据此保证真实视觉模型对所有抽象表情的判断质量。本节内容随0.1.2一并发布。
