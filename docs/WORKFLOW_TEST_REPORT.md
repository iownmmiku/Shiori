## 本轮七项修复与复核

在下方原流程验收后，继续修复了审查确认的七项缺陷：

1. 新配置仅选择全局对话模型时，判断、记忆和整理用途可以继承该模型；完整的旧版基础连接与明确选择继续保留，嵌入独立配置。
2. 防抖批次中的记忆、待办和提醒命令按原消息分别处理，保留各自来源与时间，普通聊天只调用一次模型；模型失败不重跑已完成的命令。
3. 本地已提交内容与未发送草稿分别保存，成功、失败、取消或状态刷新失败均不会丢失下一轮草稿；已确认成功的请求不恢复为待重发内容。
4. 自动记忆中的多个事件日期按对应来源片段关联；没有唯一依据时保持时间未知，不能把一条消息的第一个日期套给所有事件。
5. 下一轮仍在引用的附件延后释放；异步复用结果还会复核会话、发送状态和引用版本，过期结果不能重新附加已释放资料。
6. 插件入口和辅助源码统一检查解析复杂度，递归或过深的AST转换为候选级错误；同包其他合法候选仍能安装。
7. 本地聊天支持先分页读取插件，再按修订号和摘要修改；新建不能覆盖现有ID，修改保留未改的参数与资源并停用，不自动运行。

本轮整合命令覆盖新模型继承、合并命令、事件日期、时间来源、记忆候选、旧聊天、防抖、插件包与修改、配置界面、草稿及附件界面、模型异常、群聊、输出分段、引用和上下文，共 **342通过、1失败**，耗时29.34秒。失败项为 `test_model_message_parts.py::test_generation_prompt_and_chosen_parts_persist_without_second_request`，在登录夹具阶段返回 `password_file_error`，尚未进入聊天逻辑；当前受限Windows进程无法使用DPAPI，未因此修改生产密码保护实现或申请提权。这个结果不能写成整合全通过。

另外，`tests/frontend*.cjs` **23套全部通过**。插件专项66项通过；补充旧插件权限与真实子进程回归后88项通过，旧API登录使用仅测试进程内的加密夹具，不代表真实DPAPI已验收。附件、流式和界面相关集44项通过、6项因同一DPAPI边界被明确排除。其他旧模型密钥与时间界面测试也有同类环境阻碍，未计为行为验证通过。各组检查存在重叠，不将数量相加。

本轮 `git diff --check`通过，版本仍为0.1.5，没有提交、推送、重建安装包或操作生产服务器。当前仍未验证真实QQ、用户供应商或收费模型。
