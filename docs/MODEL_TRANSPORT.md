# 模型响应、超时与用量核对

本文描述 mikubot 的流式传输、超时、备用调用与消费记录。本次0.1.4重建包含断流兼容、后台重试和人格专用路由；下载过旧包的用户需重新下载。

模型供应商的对话模型参数提供三种响应方式：自动、流式、普通JSON。自动优先请求流式；仅当服务明确以400拒绝流式参数时才协商普通响应，不会在已接受生成后悄悄重新请求。不支持流式用量选项的服务可单独退掉该选项。兼容服务即使直接返回JSON也可使用。

流式在上游逐块读取；QQ仍在完整组装后按模型生成的消息边界发送，不逐token刷屏。网页聊天增量显示生成预览，结束后用已校验和保存的最终消息替换。工具片段出现时清除预览，不展示工具参数或隐藏思考；未正常结束的流不保存为成功回复。取消会关闭上游等待并释放名额，已经发出的请求费用仍可能需要核实。

纯文本流有 `finish_reason` 或明确的 `[DONE]` 结束标记即可完成；兼容部分中转服务省略 `finish_reason` 的情况。工具流仍必须有 `finish_reason`、完整标识及可解析的JSON对象参数。只有正文后直接EOF且无结束标记的结果不会被采纳。运行日志的 `model_stream_incomplete` 记录结束标记状态、是否包含工具片段及已收字节数，不包含正文、密钥或上游原始响应；这说明客户端未收到完整结束，不能据此判断是哪一层网络中断。

首个choice结束状态固定，后续`stop`不能覆盖`length`，`[DONE]`后的数据不再采用，结果不随网络分块方式改变。用量尾帧仍可读取；完整响应之后的次要连接清理错误不覆盖已收到的结果，实际读取失败、取消和权限校验错误继续有效。

## 内容过滤响应

普通JSON或SSE返回`finish_reason: content_filter`，以及非空`refusal`字段时，统一按内容过滤处理，不把上游正文存为正式回复，也不执行该响应返回的工具。QQ显示本地编写的过滤提示；网页清除此前的临时草稿，过滤终止事件内的正文不会进入预览。已经在终止标记到达前显示的草稿无法撤销传输，因此预览始终不能当作最终结果。

内容过滤与预算不足、超时和断流分别记录；不会因过滤触发备用模型或后台分析重试。此前已完成的独立工具操作不会被回滚。运行日志的`model_content_filter`仅记录作用域、任务、模型源、过滤类型及用量确认状态，不保存上游报错原文。

服务返回的合法用量仍计入账本；缺少或无效的用量保留预留估算并标记待核实。SSE收到过滤标记后最多额外等待1秒读取用量尾帧，尾帧超时或断开不会把已确认的过滤误报成网络错误。

## 人格蒸馏与表情包识图

在“模型供应商 → 为聊天、记忆、整理和人格蒸馏选择模型”中选择“人格生成与蒸馏”。留空继承全局日常对话模型；指定后直接生成、语料及角色蒸馏都使用该模型，与聊天模型的流式设置分开。表情包页已有独立识图模型选项，必须选择支持图片输入的模型。不会替用户选择第三方模型、修改密钥或自动关闭流式。

角色资料超过12000字时，先按每段最多8000字整理所有来源，保留来源标号，再用于五维研究。摘要过长或配额不够会明确报错，不截掉尾部资料。批次与研究结果都保存检查点，重试任务可复用已完成步骤。

蒸馏及表情包识图遇到断流、响应超时或连接中断时，最多额外重试当前分析一次；只重试分析，不执行工具。蒸馏每次尝试计入任务调用及Token上限，失败估算保留为待确认；识图每次尝试计入每日识图与总调用配额。权限撤销、取消、配额耗尽及无效流格式不会自动重试。聊天默认仍不重复收费；开启“响应超时或断流后尝试备用模型”后，初次聊天、Planner和总结可按已有备用顺序回退，工具续答及电脑任务仍不重放。

## 三种等待限制

- “模型等待超时”：HTTP连接、读取空闲等阶段等待，默认90秒；连接最长12秒。读取空闲约束数据块之间的等待，不是整轮耗时。
- “首次有效内容等待”：默认90秒；SSE注释、心跳和空事件不算正文或工具参数。普通JSON无法提供真实首token指标。
- “整轮模型等待上限”：默认300秒，包含模型排队、请求与备用尝试。达到时限关闭等待；上游不保证立即停止生成或收费。

统计中的“首个有效内容延迟”只来自真实流事件，没有采集时显示未采集。连接中断、超时、无效流不会被文案里的“预算”误报为本地额度耗尽。

## Planner 计划校验

Planner只决定本轮`reply`或`skip`，不授予工具或管理员权限。模型计划必须绑定当前消息和发言人，并提供合法布尔值、理由及回复意图；不支持`wait`。无需检索时`needed_info`应为`[]`，兼容旧提示词导致的省略，但不把显式错误类型改成有效计划。JSON解析只兼容BOM及完整代码围栏，不猜测或修补残缺结果，不为修补格式额外调用模型。

当前Planner单次输出最多350tokens，包含模型思考；模型自身配置或剩余预算还可能进一步收紧。普通对话模型的更大输出上限不会突破该规划上限。本轮保持现有额度，深度思考模型仍可能在计划完成前耗尽；尚未提供Planner独立输出额度配置。

直接请求出现无效计划时会给出格式错误提示；无直接触发的主动规划错误不会向群内刷屏。运行日志的`planner_error`和状态中的`error_code`可区分JSON错误、缺失/无效字段、目标不符及请求失败；诊断不包含模型原始正文。有效的语义`skip`仍表示模型选择不回复，二者不会混为一类。

## 超时后使用备用模型

默认关闭“响应超时后尝试备用模型”。连接建立失败、限流和可重试服务错误继续按原规则使用备用。响应读取超时则无法证明原请求没有收费；开启后允许初次聊天、Planner、总结生成在预算许可下尝试已配置备用，原请求仍记录待核实消费。已执行工具的续答、电脑任务和其他操作链不会因为此开关重新运行。总等待时限始终生效。

## 嵌入模型与记忆检索

独立嵌入模型的“请求超时”只影响该模型，连接等待也不会大于所设值。“资源与响应速度”里的“在线语义检索总等待”默认8秒，跨主查询和追加查询共享，包含语义锁、模型队列与查询向量；选择同步构建时也包含记忆块向量。超时使用先前算好的词法结果；用户主动取消继续取消，不伪装成正常降级。显式连接测试不使用这份在线预算。

向量缓存按授权和版本复核；冷索引默认由有界后台队列补全，本轮先使用词法结果和已有向量。后台依然计费并受预算限制，说明见[大量记忆检索](MEMORY_RETRIEVAL.md)。不会为追求响应速度把未经复核的跨会话资料发给模型。队列、缓存和输入上限说明见[低内存部署](LOW_MEMORY.md)。

## 消费待核实

统计分为服务返回用量、成功响应的本地估算、消费待核实三组。已派发请求遇到读取超时、取消或不完整响应时，暂按预留的输入与最大输出保守计入预算。它可能高于实际账单，不等于已经确认的消费，也不是在途预留再重复算一次。

服务计数仅接受安全范围内的非负整数，输入、输出各最多1亿tokens，与本地核对上限一致，避免畸形上游数值破坏账本。无法确认的过滤用量保留估算；写入失败时不提前释放内存中的消费预约，错误仍需排查数据目录和运行日志。

在运行电脑本机打开“数据统计 → 管理待核实消费”，先核对服务商账单或请求记录，再选择实际用量或确认未计费，填写依据。操作替换原记录的有效Token与金额，保留原估算和审计记录；重复提交同一操作不会重复结算。请求尝试次数不被抹去。没有自动超时清零、到期抹账或从通用接口猜测账单。

远程登录可以查看消费，但不能通过此接口核销。密钥、密码不要写入核对说明。

供应商自动账单查询尚未实现；各家公开接口的可用性和局限见[消费核对能力边界](BILLING_RECONCILIATION.md)，账户余额不能当作单次请求的计费证据。
