# 2026-10-25 本地自查

范围为当前0.1.6未发布改动，重点检查Planner、防抖、发送、模型结束状态、用量、托盘与接收名单。没有连接真实QQ、调用收费模型、修改服务器或推送GitHub。

## 确认并修复的问题

| 类别 | 触发条件与影响 | 修复 |
| --- | --- | --- |
| Planner解析卡顿 | 未闭合代码围栏包含长空白，正则回溯阻塞事件循环，异步期限无法中断 | 按固定边界线性处理围栏，保留完整JSON和容量/嵌套校验 |
| 流结束状态被覆盖 | 同一网络块中DONE后的正文继续被解析；length后来的stop能覆盖先前状态 | DONE后停止解析；首个choice结束状态固定，继续接收合法用量尾帧 |
| 过滤用量提前结束 | 尾帧已有两个用量键，但为null、负数等，无视随后可用计数并记高估算 | 仅完整可信计数才提前结束，合法实际用量不被畸形尾帧覆盖 |
| 超界用量与落盘失败 | 超大计数导致SQLite溢出；落盘前释放预约导致保守消费丢失 | 统一计数上限与现有核对上限一致；持久化成功后才释放预约 |
| 关闭连接覆盖结果 | 完整响应或内容过滤已收到，清理套接字时报错却转成模型重试/备用 | 正常EOF或已有主错误时不让次要关闭错误覆盖结果；实际读取错误、权限与取消继续传播 |
| 启动隐藏窗口失联 | 托盘在窗口创建期间失效，显示请求因窗口尚未存在而丢失 | 显示请求保留至原生创建完毕，再显示/恢复；不阻塞GUI线程 |
| 旧分段补发来源不完整 | 恢复含修订源消息/上下文/回复或时间的备份，原ID仍存在，旧正文仍可手动补发 | 新回执绑定原始请求、上下文和回复的指纹及时间，每段补发前重新校验 |

旧发送回执仍可查看，confirmed/unknown不自动重发。缺少原始指纹的旧版pending回执不再允许补发，需重新提问；不会以当前数据补造原始来源。

最终完整回归：**2166通过、3跳过、0失败，239.46秒**。本轮新增63项包含在该全量中，不与专项相加。三项跳过为两项Windows符号链接权限及一项仅POSIX适用检查。原样关闭独立复验与本轮最终全量都通过，但一次性观察仍不能证明所有长连接关闭场景已覆盖。
