# 作品角色模式

1. 先用角色名或作品名检索核心角色目录。Bangumi角色／作品接口提供角色ID、所属作品和别名，MediaWiki作为备用；使用与公开网页相同的地址校验和DNS固定连接。显示可选角色而非资料网页列表；多候选时由用户单选，不自动把第一个结果当成用户的选择。
2. 确认角色后自动整理核心资料和补充来源，保留角色ID、别名、作品与可选时间线。资料不足时记录缺口，不要求用户先准备链接才能进入正常流程。自备链接为单独的可选路径，沿用原资料确认与变更复核。
3. 分别研究：身份设定、性格和压力反应、表达习惯、关系模式、关键场景。每个结论标明 source id；原文没提供的经典台词、事件或心理不补写。
4. 对动画、游戏、漫画等跨媒体材料另写覆盖记录。主线与衍生材料分开，同名、不同版本或时间线冲突保留。
5. 将有证据的观察汇成行为蒸馏链，再组装自然的聊天人格。最终 Skill 包含 SKILL.md、persona.md、manifest.json、references/sources.json、references/distillation.md、research 六个维度和 quality-report.json。
6. 来源索引包含 URL、标题、采集时间、内容摘要 hash、来源类型、失败记录。来源类型只是检索线索；不能把 Wiki 或多个域名标成官方验证。关键事实不足两个独立来源时标明未交叉验证。
7. 排除知乎、微信公众号、百度百科作为角色证据。重要行为应跨场景出现；原资料不支持 3—7 个核心行为时，记录不足，不能为了达标编造场景。
8. Skill 明确资料检索日期和资料更新回应方式。新资料不自动覆盖旧时间线，更新时保留冲突。
