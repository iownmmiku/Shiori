# Shiori 0.2.1-beta 使用指南

本文描述 Shiori 0.2.1-beta 的聊天、模型、QQ、人格、记忆、电脑任务与角色日程流程。界面采用 Analysis OS 视觉样式。[更新日志](https://github.com/iownmmiku/Shiori/blob/main/RELEASE_NOTES.md)与[测试报告](https://github.com/iownmmiku/Shiori/blob/main/TEST_REPORT.md)说明变化和实际验收范围，升级前保留完整数据副本。

Shiori 是本机运行的聊天机器人和任务助手。默认人格为初音未来，可以在管理台聊天，也可以接入 NapCat、SnowLuma 或 QQ 官方机器人。电脑任务由管理员发起；普通聊天用户不会因能聊天而获得管理员权限。

第一次使用的最短路径：下载并打开软件 → 设置登录密码 → 快速入门中添加供应商、获取并选择聊天模型 → 打开“Chat 工作台”发消息。默认名称可以直接沿用，QQ 和电脑能力可以稍后开启。

在 [GitHub Releases 0.2.0](https://github.com/iownmmiku/Shiori/releases/tag/v0.2.0) 的 Assets 中下载：`shiori-0.2.0-Windows-Setup.exe` 是推荐安装版；`shiori-0.2.0-Windows-x64.zip` 是完整解压后运行的便携版；`shiori-0.2.0-source.zip` 需要 Python 3.11–3.13（推荐3.12）。安装包未做 Windows 代码签名，运行前核对旁置同名 `.sha256`。安装版与便携版无需 Python 或 Node，也不包含模型密钥、QQ 客户端和连接器。

测试版文件为 `shiori-0.2.1-beta-Windows-Setup.exe`、`shiori-0.2.1-beta-Windows-x64.zip` 和 `shiori-0.2.1-beta-source.zip`，见 [0.2.1-beta 预发布页](https://github.com/iownmmiku/Shiori/releases/tag/v0.2.1-beta)。0.2.0 用户可在“版本与更新”开启“显示测试版”再选择。此前 beta 用户重新检查后可切换同一版本，或重新下载覆盖安装；文件名与版本号未变，请核对本次 SHA-256。测试版不替代正式版，试用时使用单独的数据副本。

## Chat 工作台与 QQ 聊天管理

两个入口位于管理台侧栏顶部。**Chat 工作台**是本地对话页面，也可在原服务地址后加 `/chat` 直接打开，沿用同一登录。工作台顶部“返回机器人管理”回到管理台；手机和小窗口通过左上角“打开项目与对话”展开项目侧栏。

点击“新建项目”，填写名称和可选说明；选择项目后点“新对话”，新会话会放入该项目。搜索框按项目名或会话名筛选；项目旁的管理按钮可改名、修改说明或解除项目分组，会话旁的管理按钮可改名、移动、置顶、归档和恢复。旧本地会话保留在“未分组”。项目仅分类，不自动共享记忆、资料或电脑工作目录；删除项目不会删除对话历史。

Chat 首次显示最近 80 条记录；向上点击“加载更早记录”可继续查看旧对话，点击“回到最新”返回最近消息。页面最多保留 500 条记录，继续向前加载会移出较新的显示内容，不删除数据库中的历史。

聊天顶部选择本会话模型或继承全局模型，底部上传图片、参考资料并直接描述目标。**本地 Chat 只有一个输入框，不再切换“普通聊天 / 电脑任务”**：模型根据请求使用已启用的记忆、搜索、文件、Shell/Python、插件及 MCP；工具结果返回原对话后继续处理。电脑能力只需在全局开启一次，各项目沿用现有权限和工作目录；未开启时仍可正常聊天，输入框提供设置入口。

聊天里可以展开执行记录，查看实际结果、审批、停止和下载产物；完成后保留近期卡片，历史回复的“查看执行记录”可打开关联任务。点击“停止本轮”、退出登录或断开当前聊天请求会取消该轮内联电脑操作并等待子进程清理，已经完成的改动不会撤销。QQ 或其他入口单独创建的后台任务仍需在任务卡片停止。

当前页面运行期间，切换会话或管理页会保留未发送的文字、图片和资料；尚在收集的防抖消息退回原会话草稿。正在生成时可以浏览其他会话，但需等待当前生成结束再发送下一轮。草稿暂存在页面内存，刷新或关闭页面不保证保留；退出登录会清除草稿。参考资料上传期间若离开原页面或已发送下一轮，迟到的附件不会附加到新草稿；回到原聊天重新选择即可。

**QQ 聊天管理**用于监视已收到的 QQ 群聊与私聊，可按类型、名称或号码筛选，查看较早消息及实际交付记录。默认每 5 秒刷新当前消息，会话列表每分钟更新，也可手动刷新或关闭自动刷新；切页或隐藏标签后停止轮询。没有发送回执的消息会明确显示未知状态，不将“模型已生成”当作“QQ 已送达”。此页只读；通过“会话配置”调整该会话，通过“运行日志”排查异常。NapCat、SnowLuma 和官方 QQ 会话均可查看。连接器只提供文件标识的图片会显示“QQ图片（回复时读取）”，待回复处理时解析。

当前消息窗口最多保留 500 条，完整记录仍在数据库中。点击“加载更早记录”进入历史浏览，自动刷新只更新会话列表和送达回执，不将正在阅读的旧消息挤出窗口；点击“回到最新”恢复跟进新消息。

项目与会话组织数据写入本地数据库并随完整备份保存。项目说明当前只用于管理，不会自动作为模型提示词。此功能尚未包含在稳定版 0.2.0 安装文件中。

## 集中的配置入口

0.2.1-beta 新增独立的 **自动化 → 角色日程** 页面，可管理人格周表、每日安排、节庆、纪念日与生活日记，并选择是否按忙闲状态延迟合并回复。功能默认关闭，日记独立于真实记忆，详见[角色日程使用说明](https://github.com/iownmmiku/Shiori/blob/main/docs/CHARACTER_SCHEDULE.md)。此功能尚未包含在已发布的 0.2.0 安装文件中。

**机器人配置 → 网页搜索**支持公共搜索、Tavily、DeepSeek Search、Brave Search，聊天和后台通用搜索共用。填写对应密钥、保存并测试即可；每日上限和失败回退可单独设置，详见[网页搜索](https://github.com/iownmmiku/Shiori/blob/main/docs/WEB_SEARCH.md)。此入口随0.1.6正式版提供，原beta包不包含。

机器人相关设置集中在“机器人配置”：基本配置管理名称、人格和现实时间；模型管理供应商、对话与嵌入模型及高级分工；回复与记忆调整防抖、分段和学习；QQ 连接完成接入；电脑与管理员管理任务权限；人格库提供生成、蒸馏、编辑和删除。初音未来也可以删除，最后一个人格删除后使用普通助手，重启不会重新添加。

配置表单的未保存修改保存在当前页面内存中，切换页面或保存同页另一份表单后可继续编辑；后台聊天结束不会刷新正在编辑的配置。浏览器整页刷新、关闭或退出登录会清除这些草稿，正式生效仍需点击保存。

新配置默认黑名单，不用逐个添加 QQ 号和群号。收到的聊天自动进入“群与会话”，未单独配置时继承默认；需要时可一键屏蔽、单独设置或恢复默认。旧白名单保留，可在“QQ 连接”明确切换。记忆默认隔离，配置相同不会自动共享记忆。

会话编辑只保存真正修改的项目，单改名称不会固定其他默认设置。在“逐项恢复配置继承”中勾选需要撤销的覆盖；保存后这些项目继续跟随统一配置，其他会话设置不变。“每条必回复”可用于私聊或群聊，仍遵守防抖合并、暂停、接收名单和日程规则。

版本和更新入口位于每页右上角。快速入门的底部操作区固定，正文可以滚动；选择安装父目录后会自动创建一层 `shiori` 文件夹。

### 调整侧边栏

侧边栏底部的“管理侧边栏”可以管理分类和页面：分类可改名、选择图标、上下排序或隐藏，页面可以移入其他分类、设为“未分类”或隐藏。删除分类会把其中页面移到未分类，保留功能与数据；“恢复默认”还原布局。Chat 工作台、QQ 聊天管理、运行概览和管理入口始终保留，隐藏当前页面后会回到 Chat。模型配置仍集中在“机器人配置 → 模型”，旧模型页链接自动跳转。

布局仅保存在当前浏览器，不会修改机器人配置或跨设备同步。遇到较新版本保存的布局时，本版本以临时视图打开，调整和恢复默认不会覆盖原存档；界面会明确提示。切回支持该存档的新版本后可以继续使用原布局。

## 嵌入模型与语义检索

入口为 **机器人配置 → 模型 → 嵌入模型**，与“对话模型”并列。点击“添加嵌入模型”，选择已有供应商，或新建供应商填写兼容 OpenAI 的API地址与密钥；获取模型列表后选择嵌入型号，也可直接手填准确名称。点击“保存、测试并启用检索”即可完成配置，无需另外指定任务分工或再开启记忆设置中的开关。

测试会向 `/embeddings` 发送一条短文本，校验返回向量并计入模型用量；成功后显示维度和耗时，再切换当前检索模型。失败时保留已保存的供应商和型号，方便修正后重试，原检索模型与开关不改变。不要在此填写聊天型号或上传本地模型文件；本地模型需要先运行提供该兼容接口的服务。

页面显示当前检索模型、启用状态和供应商。可单独“测试连接”（不更换当前选择）、“测试并用于检索”、修改单价与超时、停用或删除。关闭语义检索会保留配置并使用基础检索；在用型号需先切换到其他型号后删除。嵌入模型不会替换聊天模型，所有聊天共用该检索服务，记忆可见性仍遵守各会话的隔离规则。

旧版 `memory.embedding_model` 和独立嵌入路由保持兼容，查看页面不会自动迁移或改写；原默认服务下的独立嵌入型号可在本页直接测试和启用。配置后可到“知识与检索 → 召回试验台”搜索已有记忆，在召回诊断中检查是否使用语义增强。

## 0. 首次登录、密码与数据目录

Windows 安装版和便携版默认打开独立桌面窗口，不必另外打开 WebUI。桌面与浏览器使用同一套登录保护。第一次启动，在运行 Shiori 的电脑上设置至少 8 个字符的管理密码，并再次输入确认；之后输入此密码登录。没有默认密码，也不需要填写模型密钥来登录。

只在这台电脑使用时，展开“只在这台电脑使用，不设置密码”，明确勾选后启用“仅本机免密”。此模式关闭远程入口，只接受本机回环访问。需要从其他设备使用时，先在本机“登录与远程管理”设置密码，再开启远程访问。

### 从其他设备打开

在“系统设置 → 登录与远程管理”开启远程入口，保留 `0.0.0.0` 接受本机各网卡连接，或填写运行电脑的局域网 IP；指定端口，保存并重启。远程入口默认要求HTTPS：填写自己的HTTPS域名，点击“生成HTTPS部署配置”并完成代理部署。仅在可信局域网明确勾选允许HTTP后，其他设备才可使用 `http://运行电脑的实际IP:端口/` 登录。`0.0.0.0` 是监听方式，不是其他设备访问的地址。Windows 防火墙需允许对应端口，页面显示“已保存”不代表重启后的网络已经可达。

远程登录能访问聊天、设置与管理员功能。普通 HTTP 不加密密码和会话传输；仅在可信网络使用，跨不可信网络请配置 HTTPS 反向代理或加密隧道。不要把端口直接暴露到公网。远程页面不能抢先创建密码；未设密时只提示回到运行电脑完成。

使用自己的 HTTPS 域名时，可直接在网络设置填写；也可在实际 `settings.json` 的 `webui` 段设置 `allowed_hosts`（例如 `["bot.example.com"]`）和 `public_url`（例如 `"https://bot.example.com"`），同时启用远程入口。代理需保留该域名的 Host，不能重写成本机地址；外部不转发 `/api/auth/bootstrap`、`/api/auth/setup`、`/api/session`。初始化链接与本机令牌不用于远程登录。完整配置和 TLS、防火墙要求见[源码部署指南](https://github.com/iownmmiku/Shiori/blob/main/docs/SOURCE_DEPLOY.md#使用-https-反向代理)。

“退出登录”只退出当前登录，不停止机器人。修改密码会让其他旧登录会话失效。电脑能力需单独开启，默认采用自动执行；本机模式下，管理员在允许会话中的 MCP 调用也可自动执行。Docker 隔离模式默认禁用沙箱外 MCP；确有需要时在电脑任务高级设置开启“允许沙箱外 MCP 工具”，其执行仍不在容器内。关闭电脑能力或切换为逐次审批模式后，MCP 调用需要批准。

### 密码保存在哪里，忘记了怎么办

默认数据目录为 `%LOCALAPPDATA%\shiori\data`，通常对应 `C:\Users\你的用户名\AppData\Local\shiori\data`，独立于程序安装位置。专用密码文件为该目录中的 `security\webui-password.json`。本机登录页和设置会显示本次实际路径；自定义 `--data-dir` 时以该路径为准。

文件不保存明文密码，而是加盐的 scrypt 校验值；Windows 还使用当前 Windows 账户的 DPAPI 对记录加密。非 Windows 使用加盐校验值与私有文件权限。登录 Cookie 为 HttpOnly，浏览器不会把密码写入本地存储，应用备份不导出密码文件。请保护数据目录的系统访问权限；能删除密码文件的人可在本机重设密码。

优先在运行电脑的托盘菜单选择“重置 WebUI 密码”，按本机提示重新设密；无托盘时可执行 `python -m shiori --data-dir 实际数据目录 --reset-password`。此入口不开放给远程网页。仍可手动恢复：

1. 完全退出 Shiori，包括托盘中的程序。
2. 打开实际数据目录，只删除 `security\webui-password.json`。不要删除数据库、`security` 文件夹或整个数据目录。
3. 重新打开 Shiori 桌面客户端，程序会检测缺失并创建待初始化记录；在运行电脑上设置新密码。
4. 其他设备使用新密码重新登录。旧登录会话失效，聊天、记忆和模型配置保留。

密码文件损坏或换 Windows 账户后不能解密时，也可使用此恢复流程。删除文件不会让远程页面直接免密进入。

### 程序与数据分开保存

移除或替换安装目录时保留上述数据目录，重新安装后可以继续使用。需要迁移时先退出程序，复制完整数据目录，再用 `--data-dir` 指向它；不要让两个实例同时写同一份数据。

从旧版升级：当新版默认数据目录不存在或全空，且程序旁旧 `data` 有数据时，会复制到新位置，原目录完整保留；新位置已有数据时不覆盖、不合并。指定 `--data-dir` 时不自动迁移。旧目录含链接或无法读取的特殊文件时会停止迁移并提示，可以显式使用原数据路径。

## 1. 先完成一次聊天

安装版双击 Shiori 快捷方式，便携版完整解压后运行 `shiori.exe`。程序打开桌面主窗口并在 Windows 托盘运行。托盘“在浏览器打开”或 `shiori.exe --browser` 可使用浏览器；不需要同时打开两个窗口。源码启动见 [源码部署指南](https://github.com/iownmmiku/Shiori/blob/main/docs/SOURCE_DEPLOY.md)。

桌面窗口需要 Microsoft Edge WebView2 运行时。缺失或启动失败时自动改用默认浏览器继续，并尝试发送不阻塞操作的托盘通知；系统通知不可用时仍继续运行，切换原因可在运行日志查看。下次启动仍优先桌面窗口。有托盘时关窗隐藏到后台，托盘可重新打开；`--no-tray` 模式关窗会退出。`--no-browser` 保留纯后台启动方式。

托盘会核验 Windows 是否真正注册图标，启动时短暂失败会重试；运行中丢失会尝试恢复。托盘无法使用时，主窗口不会继续隐藏在后台，关闭窗口将完整退出。便携包也提供“退出 shiori.cmd”，可双击停止默认数据目录中的实例；使用自定义数据目录时可运行 `退出 shiori.cmd --data-dir "实际数据目录"`，不需要结束任务管理器中的进程。

先连接一个模型即可开始。在快速入门点击“添加供应商并选择模型”，选择供应商模板，填写 API Key，按需调整 API 地址，系统从实际返回的目录中推荐并预选聊天模型，可直接点击“测试并用于聊天”，也可改选。DeepSeek 预设补齐 deepseek-chat；目录不含此型号时推荐目录内候选。推荐不保证模型能力或价格，也不会自动发送聊天请求。短文本测试通过后才将它设为聊天模型；测试失败保留原来的默认路由。测试会调用模型并计入用量。API 地址应以服务商文档为准，兼容接口通常以 `/v1` 结尾，不要填网页聊天地址。没有模型列表接口时可手填准确的模型名。已有模型可直接选择沿用，只修改聊天路由，保留密钥和其他任务分工。之后也可在设置中再次测试连接。只有确实支持工具调用或图片的模型，才能使用对应能力，无法从模型名称推断兼容性。

从“机器人配置 → 模型”新增供应商时，单独保存连接不会替换原有路由；继续选择“设为聊天模型”，或从聊天顶栏为当前会话选择。快速入门的专用流程会直接完成此选择。

首次不需要修改默认名称，也不必同时配置 QQ、多个模型和电脑任务。可以跳过模型先查看界面，使用已提供的记事、计算、待办等本地功能；自然对话、人格蒸馏和电脑任务需要可用模型。

进入“聊天”，新建对话并发送“你好”。会话 ID 自动生成。左侧选择会话，右侧查看消息；本地会话默认回应每条消息。QQ 群聊可以使用“被提及时回应”“自然陪伴”等预设，详细触发规则在会话设置中调整。

### 单独管理供应商和模型

打开“机器人配置 → 模型”，左侧是连接来源，右侧是它的模型目录。点击“添加供应商”，填写名称、API 地址和密钥；连接信息填好后会自动读取当前表单的模型列表，也可点击“立即获取模型”。勾选需要的模型后保存，一套连接可以添加多个模型，不必重复填写密钥。服务没有目录接口时，可按其文档手动填写模型名称。

模型可以独立启停、删除、修改显示名称、价格和图片/工具配置；目录只说明服务公布了模型，不能保证其实际能力。全局聊天模型可在卡片直接设置，记忆、Planner、整理等用途在下方高级分工选择。新配置留空时，这些用途继承全局对话模型；旧版已完整填写的基础默认连接继续保留。嵌入模型需独立设置。聊天顶栏的“本会话模型”只影响当前会话，选择“继承全局聊天模型”恢复默认。

原有单模型配置与密钥继续保留，以“原有配置”来源展示，仍可从原设置编辑。删除模型前先解除其全局路由和会话选择；删除供应商前先移除旗下模型，软件不会悄悄替换正在使用的模型。单价未知继续显示费用未知。

## 2. 名称、人格与回复习惯

在“机器人配置”修改机器人名称和别名。“被 @ 时直接回复”和“提及名称时直接回复”开启时，群聊跳过 Planner 判断，直接生成回答；关闭时仍识别提及，单独交给 Planner 决定回应或跳过，不必等待普通群消息集中判断。会话可继承全局设置，也可以单独覆盖。引用回复的触发开关保持独立。

开启消息防抖后，先合并同群连续输入，再按上述方式处理一次。若当前会话的有效 Planner 开关也关闭，且对应“直接回复”关闭，则不会仅因 @ 或名称提及回复；未配置可用判断模型时同样不强制回复。暂停、接收名单、来源与工具权限，以及已启用的日程延后规则始终生效。

在“机器人配置 → 基本配置 → 现实时间”开关“感知现实时间”。默认开启，每轮对话和 Planner 获知配置时区下的当前日期、时间、星期和 UTC 偏移；关闭后不再主动提供当前时钟，历史消息、用户提供的日期、提醒、配额和统计仍照常保留。时区修改即时生效，不需要重启。

时间预览来自运行Shiori的设备，检测到与浏览器的明显偏差时会提示核对。消息分别保留平台发送、接收和录入时间；相对日期优先参照原消息，而非排队后开始回复的时间。同一消息中的事件分别匹配日期，无法唯一确定时保留未知，不把“今天去海边，昨天看电影”都记成今天。

### 等你说完再回复

在“机器人配置 → 回复与记忆”开启消息防抖。默认关闭，开启后的初始等待为3秒；期间每条新消息重新计时，最长收集默认30秒。普通等待可设0.1—60秒，最长收集可设1—300秒且不得更短。群聊按群统一收集，不同成员连续 @ 或补充消息共用一个等待窗口，统一判断和回复；每条原消息的发送者和权限仍独立保留。私聊仍按当前对话收集，开启后不再叠加原有群聊短窗口；关闭后恢复原有回复流程。

上一轮已经开始生成或发送时会继续完成；同群尚在等待处理的后续消息会继续合入下一轮，直到实际开始处理。停止收集只移除本人的待处理内容，不清空其他成员的消息。例如不同成员在第0、2、4秒各发一句话，三秒防抖会在约第7秒启动一次回复流程。防抖合并的是输入，一次回答仍可能按独立的“回复分段”设置发出多条气泡。运行日志中的 `qq_debounce` 会记录合并的输入数量，方便区分一轮回答分段和重复启动多轮回答。

本地聊天显示待发送条数，可“立即回复”或“取消收集”。提交内容与下一轮未发送草稿分开保留，附件仍被草稿引用时不提前释放；刷新或关闭页面不能保证恢复。单轮最多收集8条，达到条数或图片等容量后先处理一轮，后续消息进入下一轮。最长收集时间不包含模型处理、排队和发送耗时。本地统一 Chat 的工具操作沿用同一管理员的实际原消息与权限，QQ 独立电脑任务仍直接提交，不借用其他成员的消息扩大授权。

记忆、待办和提醒命令按每条原消息处理。例如连续发送“记住：我喜欢咖啡”和“今天聊什么”，只记住咖啡偏好，再回答普通问题。不同成员的命令按各自身份、权限和原始来源处理，不因统一回复获得其他人的权限，也不把他人的话拼成命令参数。已经完成的命令保留回执，后续模型失败不会自动重做。多人合并时，模型只使用检索、计算等只读工具；电脑任务、插件和 MCP 操作请单独发送明确指令。全局防抖可被机器人配置和单会话覆盖，留空表示继承。

QQ 多段回复开始发送后，普通追问会排在后面，不会仅因新消息而丢弃旧回复的尾段。单个请求人可用“停止回复”或改问中止自己的回复；多人合并的回复已经开始处理时，一个成员的停止或改问不会取消整轮回复。暂停、撤销权限或来源失效仍会阻止后续发送；平台没有确认送达时停止并记录已确认条数，不自动重复投递未知消息。

交给 Planner 的消息先判断是否对自己说、是否值得参与，再决定生成回复或跳过，不提供 `wait` 动作。开启“直接回复”的 @ 与名称提及不经过这次判断。群聊陪伴预设将 @ 和名称提及交给 Planner；需要某个私聊每条必回时，使用私聊必回复预设。主动接话仍由独立开关控制。

默认只保留初音未来人格。在“机器人配置与人格”中，上方管理统一配置，下方管理人格库。配置集中选择人格、模型和回复规则，新聊天默认继承；已有聊天保留旧独立设置，可点击“绑定聊天”批量迁入。绑定清除配置覆盖，聊天记录、记忆与共享空间不变。“设为默认人格”修改默认配置，不再只修改当前会话。

人格可以手动编写、按描述直接生成，或从作品角色／已有语料蒸馏。生成结果先预览、试聊，保存进入人格库后再选择应用。完整角色 Skill 是资料产物，不自动改变工具权限。

## 3. 连接本机 QQ

### NapCat 或 SnowLuma

1. 先独立安装并启动连接器，登录 QQ；Shiori 安装包不包含 QQ 客户端或连接器。
2. 在快速入门选择连接器，点击“保存并自动配对”；新配置默认黑名单，无需先填账号。已有配置也可从“机器人配置 → QQ 连接”打开本机配对入口。
3. 填写连接器 WebUI 地址及管理口令。此口令与 Shiori 登录密码、模型 API Key 不同。有两步验证时填写当前验证码；SnowLuma 多账号时选择实际使用的 QQ。
4. 点击连接。Shiori 通过连接器官方 WebUI 接口添加专属反向 WebSocket，保留其他连接。
5. 查看 Shiori 中的实际在线状态，再用允许的私聊或群聊发送测试消息，检查回复是否送达。

默认探测 NapCat 的 `http://127.0.0.1:6099` 和 SnowLuma 的 `http://127.0.0.1:5099`，端口可手动修改。“端口有响应”仅表示存在本机 Web 服务，填写口令验证后才知道是否能自动配置。管理口令不保存；不要把它与 OneBot 连接密钥混淆。

配对重复执行只更新 Shiori 专属连接，不清空连接器配置。热加载没有确认成功时，先打开 WebUI 检查，再查看实际连接状态。撤销入口只删除本次配对识别的专属项；专属项被其他窗口修改后会停止撤销，需要人工核对。

自动配对仅支持本机回环地址。未知配置版本、Docker、WSL、远程 QQ 客户端可使用手动方式：在连接器添加反向 WebSocket，填入页面显示的 `/onebot/v11/ws` 地址与相同的 Access Token。首次 QQ 扫码、设备确认和连接器初始化仍需要你完成。

### QQ 官方机器人

在 QQ 开放平台申请应用，填写 AppID、AppSecret，再启用官方机器人。官方用户和群使用 OpenID，不是普通 QQ 数字号；按平台实际权限、可用场景和审核要求使用。允许聊天的 OpenID 不自动变成管理员。

### 谁可以与机器人聊天

新配置默认使用黑名单，未屏蔽的私聊和群无需逐个添加。需要限制接收范围时可明确选择白名单，再填写允许的用户和群；旧白名单保持原样。可聊天的会话仍可在“群与会话”中暂停、关闭工具或调整回复策略。确认顺序是：连接器登录、WebSocket 在线、聊天未被接收规则屏蔽、模型可用、回复送达。

### 连接成功但没有回复

在“机器人配置 → QQ 连接”的“消息接收与回复”查看消息数、心跳数和最近处理原因，再打开“运行日志”按关键词搜索。只有心跳没有消息时，检查连接器是否开启消息上报；有消息却被拒绝时，检查允许的私聊/群、暂停开关、会话启用状态和 Planner；已生成但未送达时，检查发送错误与连接器日志。

QQ 是否可聊天由当前选择的黑名单或白名单规则决定，管理员列表单独授予电脑能力。默认私聊每条回应；明确开启了 Planner 的会话仍保留自己的策略。配置后先核对接收规则，再用自己的实际账号发送测试消息。本版使用模拟连接器与本地消息链路回归，不等于已验证你的真实 QQ 环境。

## 4. 管理员：聊天权限与电脑权限分开

默认管理员 `shiori` 是**通过管理台认证的本地账户**，不是昵称为 Shiori 的 QQ 账号。本地管理员不能从列表中移除；管理台凭据保存在本机。

管理员列表支持多个 QQ 账号，按平台与真实发送者 ID 判断；通过配对码绑定会同时记录机器人实例。手动账号的实例留空时，会匹配该平台同账号；建议填写实际实例以限定范围。群主、群管理员、昵称、自称“主人”、转发或引用别人的管理员命令，都不会授予电脑权限。

不知道自己的官方 OpenID 或希望核实身份时，使用“绑定我的 QQ”：

1. 在管理员页面点击“60秒快速配对”，配对码仅交给自己的目标账号。
2. 用该 QQ 私聊机器人发送完整的 `/绑定 配对码`；签名校验通过即成为该实例的管理员，同时加入允许私聊名单。
3. 页面自动显示绑定结果，配对码单次使用、60秒后过期，重启也失效。

需要人工核对时选择“手动核对配对”；此模式收到消息后只登记候选，回到页面核对账号和实例后确认。其他允许聊天账号不会批量提权。不再需要的管理员可移除。

允许的聊天中发送 `/身份` 可查看当前真实身份。移除 QQ 管理员不会删除其普通聊天资格；需要同时禁止聊天时再调整允许列表。任务每一步都会重新检查管理员资格，移除账号或关闭电脑能力后，后续步骤停止。

## 5. 电脑任务：Shell、Python 和文件操作

在“机器人配置 → 电脑与管理员”开启能力，选择专用工作文件夹并保存。默认工作位置为数据目录下的 `workspace`，本地 Chat 默认最多 12 轮工具处理，每轮最多 4 个调用，每条命令超时 60 秒；高级设置可调整。回到 Chat 直接发送要求，无需切换模式或为每个项目重新开启。文件读取支持按 Unicode 字符位置续读；较早的工具结果会压缩为回执，完整结果仍保存在执行记录中。本版提供 Shell、Python、文件读取、搜索、新建与修改，不提供鼠标键盘、屏幕截图循环。新安装默认选择 Docker 隔离代码执行；已有本机模式不会强制迁移。

管理员可以在聊天中提出明确任务，例如：

`帮我读取工作目录中的日志，分析报错原因，生成一份摘要。`

本地 Chat 会在同一对话里完成必要的读取、修改、运行与核验，不再把每轮要求交给另一个缺少对话历史的电脑任务模型。QQ 管理员仍可发送 `/执行 读取工作目录的日志并生成摘要`；使用 `/任务 任务编号` 查看，`/停止 任务编号` 停止。普通用户、未允许的 QQ 会话、已暂停的机器人不能发动电脑任务。

默认自动执行模式下，管理员明确提出的任务连续执行，文件写入、Shell 与 Python 不再逐步等待批准。任务会记录具体步骤、路径和运行结果，可随时在任务卡片或后台任务页停止。读文件、列目录和文本搜索限定在选定工作目录；请只向可信管理员开放此能力。

选择 Docker 时，Shell/Python 在本机 Linux 容器中执行，默认断网、只读系统、限制资源，只映射工作目录。Docker 沙箱隔离主机系统，不保护工作目录内的文件；/workspace 是可写映射，脚本可在其中增删文件。先安装并启动 Docker，再手动运行 `docker pull docker.io/library/python:3.12-slim@sha256:a6e34c598f2467ed0e9a8d349809fcd8b5c603269512df273a0bb1784edc11b1`，点击“检查隔离环境”。不可用时任务停止，不会自动退回本机执行。沙箱使用 POSIX Shell，不能直接运行宿主 Windows GUI。选择“本机账户权限”时，Shell、Python 使用当前系统账户权限，工作目录不是隔离沙箱。安装/便携版的 Python 由随包运行环境执行，可用第三方模块以发行包为准；源码版使用当前虚拟环境。软件内的文本修改检查原文件变化并保留副本。命令本身产生的外部影响不能仅靠关闭聊天撤回。

在任务记录中查看进度、工具结果、已完成、失败或停止状态。成功任务中的新增或修改文件可提供下载入口；文件完成后又被修改时，需要到工作目录核对当前版本。任务完成和 QQ 通知是否送达分别记录。本地 Chat 内联任务随本轮停止或连接关闭而取消，独立后台任务可以继续运行，重新打开可查看。停止会阻止后续操作，已经发生的写入或发送不会自动撤销。程序退出、重启后未完成任务标为中断，**不会自动重跑历史命令**；先检查已有结果，再新建后续任务。超时、停止或连接丢失时结果可能不确定，先核对文件、进程和外部服务状态，不直接重发同一个操作。

Docker 隔离仅适用于内置 Shell/Python，文件工具仍由宿主进程在工作目录内操作；MCP 服务不被此容器隔离，Docker 电脑能力开启时默认禁用；若需使用，须在电脑任务高级设置明确开启“允许沙箱外 MCP 工具”。MCP 扩展始终受管理员身份、会话权限、服务与工具允许列表限制。电脑能力开启且 `computer.approval_mode` 为默认的 `automatic` 时，管理员在允许会话中的 MCP 调用也自动执行，包括普通聊天提出的调用。关闭电脑能力，或将该模式改为 `per_action` 时，需要逐次批准。启用某个人格或下载其 Skill 不会绕过这些权限。

逐步确认模式下，同一管理员在原会话回复“同意/确认/拒绝”即可处理唯一待审批动作，5分钟过期。有多个待审批任务时仍需完整任务编号与审批码；自动模式不增加确认。

本地 Chat 内联电脑操作在当前任务卡片批准后继续同一轮处理；MCP 的手动审批仍沿用现有调用记录及结果摘要流程。已配置并授权的本地 MCP 目录会在需要时自动刷新，刷新失败不会使用过期工具定义，也不会自动扩大服务或工具允许列表。

## 6. 生成或蒸馏一个人格

在“机器人配置与人格”选择“直接生成”或“蒸馏人格”。这些操作产生草稿，不直接覆盖现有人格；先预览和试聊，确定后保存到人格库。

### 按描述直接生成

输入希望的性格、表达习惯、兴趣及互动方式，可选填名称。直接生成不需要上传材料，不检索网页，也不生成 Skill。描述发送给已配置的模型并计入用量，结果可在后台任务中查看、试聊和保存。

### 从作品角色蒸馏

角色蒸馏流程：输入一个角色名或作品名，点击“检索角色”，在角色列表中选择对象，再点击“确认角色并开始蒸馏”。例如输入“和泉纱雾”会显示姓名、别名、作品和简介；只输入“埃罗芒阿老师”则列出该作品的角色。无需准备链接、逐个勾选资料网页或再打开确认开关。

检索优先使用核心站点的角色／作品接口，识别日文名和站点列出的中文别名；角色目录不可用时尝试 MediaWiki 资料接口。检索不调用模型。确认后自动整理实际读取的资料，再开始五个研究维度、行为提炼与人格描写；此阶段计入模型用量。作品范围、自备资料链接、采用版本和另存名称放在可选项，同名角色和不同时间线仍需核对。指定资料时最多6个公开链接，继续使用原来的资料确认流程。

结果包含可用于聊天的人格与可下载的角色 Skill ZIP，包内保留来源、研究、边界和结构检查信息。搜索结果或多来源并不自动代表官方设定；资料不足处应保留未知，人工审阅后再使用。自动整理的资料及角色别名随任务留存，并支持检查点恢复；自备资料模式仍复核用户确认后的来源变更。角色检索、专用模型、研究检查点与恢复流程均包含在 0.1.5 中。

### 从已有语料蒸馏

上传 ZIP 或支持的单文件。软件先给出可读文件、跳过原因、字符数与识别出的说话者；选择材料和目标人物后再确认分析。多说话者聊天记录需明确选择目标，别人的发言只作上下文。

支持 TXT、MD、CSV、JSON、JSONL、HTML、SRT、VTT、文字层 PDF、DOCX。上传上限 24MB，ZIP 解压总量上限 48MB、200 个文件，单个可读文件上限 8MB/30万字符、合计最多100万字符；不支持密码压缩包、递归嵌套解压、扫描件 OCR 或把图片当成文字语料。

这种模式仅输出独立人设描写，不生成 Skill。它也能分析真实人物的语料：描述材料中可观察的表达、互动和取舍，引用或转述不直接算作本人立场，材料没有提供的生平与内心保持未知。不会默认联网补充真人资料。

蒸馏有独立任务调用与 Token 上限，也受模型服务预算约束。材料过多、预算不足或读取失败时会明确停止，缩小文件范围后再创建任务。文件解析在本地进行；模型分析时选定文本会发送给你配置的模型服务。

未完成的蒸馏任务可在后台任务中选择“从检查点继续”。重复点击同一任务的继续按钮会沿用正在运行的续作，不另建并行任务。已完成分析和确认来源快照会复用；模型、材料或任务参数变化时拒绝旧检查点。已发出但未收到回执的模型请求可能再次计费；此机制不恢复电脑命令，也不自动重放副作用。检查点保存在数据目录中，不随脱敏备份导出，原始材料仍需保留。

## 7. 上传附件、使用记忆和资料

上传时先选择用途：

- **本次对话参考**：让模型总结、讨论当前材料，不直接写入长期记忆。
- **长期资料**：以后也需要检索，显式保存到当前会话的资料与记忆。
- **蒸馏人格**：角色或目标人物语料，进入独立蒸馏任务空间。

“本次参考”不等于从未保存：该对话和附件关联仍可能保留在会话记录中，区别是不会自动转为长期知识。发送前移除附件只是取消本次引用，不应理解为删除全部历史资料；已保存的长期资料在记忆页面管理。

聊天默认隔离。共享空间只共享明确允许共享的已确认记忆，不合并原始聊天、私人事实、任务和审批。人格公开知识可以按会话关闭；自动探索默认关闭，开启后按兴趣与来源规则收集，低置信度内容需要审核，不会自动向所有群广播。

并列兴趣分别轮换探索，“人格知识”显示实际探索时间、未运行原因和可展开的逐页过滤详情。自动探索需要全局与人格两个开关均开启；手动探索仍受每日额度和来源规则限制。详见[人格兴趣探索](https://github.com/iownmmiku/Shiori/blob/main/docs/INTEREST_EXPLORATION.md)。

常用消息：`记住：我喜欢合作游戏`、`我的记忆`、`计算：12*8`、`添加待办：整理资料`、`5分钟后提醒我喝水`。提醒需要程序运行与通道在线。

自动记忆、关系关联、重复整理、黑话与表达学习的候选都可以查看和审核。拒绝或删除会阻止旧来源继续参与回复；整理建议可以先看影响，再应用或撤销。网络热梗进入人格知识，与群内黑话分别管理。

黑话详情中的证据按原消息编号读取，支持翻页，早于最近聊天窗口的消息也能查看。原消息已删除或不属于该来源会话时显示状态提示，不再用旧摘录冒充有效证据。黑话与记忆的隔离状态分别按实际会话配置展示。

记忆档案默认显示全部会话，每条标注来源，可切换为当前聊天；此处的管理查看范围不会改变机器人召回的隔离规则。每页显示50条，底部可以翻页；搜索在所选范围内查找，切换搜索词或状态会回到第一页。需要手动关联或整理时再点击“打开关系与整理工具”。关联弹窗可以分别搜索两条较早的记忆，搜索第二条不会清掉第一条的选择。大量记忆的首次检索仍需准备分词，后续查询会复用缓存；无需删除记忆来启用这些优化。

自动整理受每日上限和持久化节奏控制，每日额度耗尽后等配置时区的下一自然日恢复；不会通过重启清空消费。模型空正文、残缺或错误格式保留原消息进度，记录原因并退避重试；合法空数组表示这一批没有值得保存的内容。页面能看到旧记忆不代表新消息已写入，请结合运行日志、候选状态与整理进度判断。真实QQ、收费模型提取质量和长期部署仍需在目标环境验收。

0.1.6正式版补齐记忆候选校验和写入时的权限复核：错误格式不再把原消息标为已整理，过期旧事实也不会阻断新消息提取。上下文参考按完整记录装入字数预算，时间检索与近期历史按消息ID去重，摘要失效时按原顺序恢复有效对话。已有记忆、每日额度及历史进度保留；旧版已漏提取的内容不会因此自动重新整理。实现与验证边界见[记忆与上下文复查](https://github.com/iownmmiku/Shiori/blob/main/docs/MEMORY_CONTEXT_AUDIT_2026-10-26.md)。

### 表情包

打开“机器人配置 → 表情包”，展开“收集与发送设置”，选择已经启用视觉能力的模型。默认使用默认聊天模型；它不支持视觉时不会尝试识图，先去“机器人配置 → 模型”配置视觉模型即可。收集和发送默认开启，概率均为 `0.1`，表示10%，可以分别调整或关闭。

只从已获准聊天的群中收集图片。采样命中后，模型先判断是不是表情包，再提取含义、分类和标签；普通照片或资料不入库。表达不明确、低置信度或无意义的条目归入“待标注”，不会自动发送。点“编辑语义与分类”可以修改含义、标签、自定义分类，并明确勾选“语义明确”。

发送概率是每次文字回复后的尝试概率：文字已确认送达后，仍要找到语义明确、符合当前上下文的表情，最多发送一张；没有合适的就不发。默认按来源群隔离；需要互通时，两个群须在同一共享记忆空间，且对该表情明确开启共享。来源消息删除、来源被遗忘、聊天被屏蔽、条目被停用或修改后，旧选择不能继续发送。NapCat / SnowLuma 发送原始图片；QQ 官方通道上传后发送静态首帧，图片发送也受平台权限与额度影响。

默认每天最多30次识图尝试，失败也计数；全库默认最多1000张、图片总大小最多128MB，单张最多2MB。识图和匹配使用模型服务，计入全局用量与预算。删除图片后保留去重标记，同一群不会立即重复收集相同图片。

表情包图片库与应用主数据库分别保存。点击“备份表情包库”可导出包含图片和语义的数据库；普通应用备份不包含它。手动恢复时先完全退出软件并保留原库，将导出的文件改名为 `library.sqlite3` 放到数据目录的 `stickers` 文件夹；恢复后仍需保留对应聊天记录，失效来源不会因替换库文件而重新获准发送。

### 群聊集中判断

在“机器人配置 → 回复与记忆 → 高级”可设置 Planner 集中判断。未启用消息防抖时，普通群消息默认积累1500毫秒，达到4条时提前判断一次；同一窗口的原始消息都保留在聊天历史里，模型结合上下文决定要不要回复，不把不同成员的办事请求合并执行。关闭“直接回复”后的 @ 或名称提及单独触发 Planner，不等待这项普通消息窗口；启用防抖时则先合并同群输入，再统一处理，不叠加两个窗口。

@、引用回复、点名和私聊不等待这个窗口；正在合并的同一请求沿用原有合并规则。静默、冷却、最小判断间隔和日预算继续有效。窗口设为0即可关闭集中判断，恢复逐条进入原有本地判断流程。

## 8. 预算、升级和备份

先使用一个模型即可；模型池与按任务分工放在高级设置。未知单价显示为“费用未知”，不应理解为免费。Token 统计与按你填写的单价估算的费用分开看，服务商实际账单为准。模型连接测试、蒸馏与电脑任务会产生真实模型调用。

设置中可限制每日 Token、费用和 Planner 配额。设为 0 表示对应配额不限，关闭功能请使用独立开关。开启费用上限前，先为所用模型填写正确单价。

自动记忆整理的“每日次数”是独立规则，0表示停止整理；每天60次时自动任务约每24分钟一轮，优先近期对话并逐步补齐历史。更新或重启不会清零当天消耗。失败会退避，合法空结果也会推进已处理进度，详情见[自动记忆整理说明](https://github.com/iownmmiku/Shiori/blob/main/docs/MEMORY_EXTRACTION_SCHEDULING.md)。

升级前下载完整备份并退出旧实例。安装版数据默认在独立的用户目录中保留，源码升级见源码指南。Windows 可在设置中开启“登录 Windows 后启动”，默认关闭。关窗后仍驻留托盘时提醒继续；完全退出后提醒与 QQ 回复暂停。

完整备份包含数据库、脱敏设置、人格知识和只读工具与后台任务历史。恢复会替换现有数据、暂停回复、关闭连接并清除密钥；重新配置并确认后再继续。历史审批不重新生效，电脑命令和外部工具操作不会因恢复备份而自动重放。蒸馏原始材料、聊天附件、生成的 Skill ZIP、电脑文件修改前副本和电脑工作目录中的文件应另行备份。应用备份不等于这些文件已打包，更不等于整个磁盘的备份。

点击“下载备份”后后台生成并显示进度，可关闭窗口后重新查看，也可取消；完成后点击下载保存到自己的设备。同一时间只生成一份，重新生成会替换上一份临时下载文件，完全退出后临时文件不保留。导出和恢复使用相同容量限制：ZIP 最大 256 MiB、解压总量最大 1 GiB、单个配置或历史 JSON 最大 16 MiB；超限会明确提示，不生成无法由应用恢复的包。数据库一致快照和最终恢复阶段仍需短暂独占，脱敏、压缩与候选验证在锁外进行。

关闭恢复页面不代表已经停止恢复。候选准备阶段会在正在进行的读写结束后取消；进入替换阶段后，程序会完成恢复或回滚，再解除维护状态。下载备份途中断开连接后仍可重新生成，不需要重启软件。

## 9. 常见卡点

遇到问题先打开“运行日志”。页面每 2 秒读取新记录，可暂停更新、按级别筛选、搜索、复制当前显示内容或下载当前筛选结果；离开此页停止轮询，不影响机器人运行。页面最多显示最近 1000 条，导出最多 2000 条。运行日志结合启动错误、QQ 消息入口和任务事件，密钥会做基础脱敏，分享前仍请检查内容。

- **界面打不开**：确认程序仍运行，从托盘重新打开；源码检查是否选择正确数据目录。
- **首次只能看到设密提示，不能输入**：当前是远程页面；回到运行电脑的桌面客户端创建密码，再从其他设备登录。
- **忘记密码**：完全退出后只删除实际数据目录中的 `security\webui-password.json`，从本机重新打开并设密。
- **桌面提示缺少运行时**：安装微软 WebView2 运行时，或显式使用 `shiori.exe --browser`。
- **桌面未出现或启动失败**：先尝试显式浏览器模式；确认使用同一数据目录，查看其中的 `runtime.log`。能进入界面时再用“运行日志”筛选错误，不能仅凭进程存在判断已启动成功。
- **保存了远程入口仍连不上**：重启后核对实际监听状态、IP、端口、网络和 Windows 防火墙；其他设备不能访问 `127.0.0.1` 或 `0.0.0.0`。
- **模型列表为空**：检查地址、密钥和服务是否提供模型列表接口，也可按服务商说明手填模型。
- **端口有响应但配对失败**：可能选错服务、口令不对、需要验证码，或连接器尚未完成初始化。
- **QQ 在线却不回复**：先看 QQ 设置中的“消息接收与回复”。只有心跳没有消息时，在连接器开启消息上报；收到消息后看提示是否被名单、暂停、会话规则或 Planner 跳过。再到运行日志核对模型与发送结果。
- **能聊天却不能电脑任务**：检查是否已确认绑定管理员、电脑能力是否启用、会话是否允许工具。
- **扩展工具等待审批**：检查电脑能力是否开启、执行模式是否为 `per_action`。Docker 隔离模式默认禁用沙箱外 MCP；高级设置开启后才允许调用。只有开启电脑能力、采用 `automatic` 且管理员和会话权限均允许时，MCP 才自动执行；需要审批时核对当前请求，不复用旧编号。
- **任务重启后没有继续**：历史命令不会自动重跑；检查已产生结果，再新建后续任务。
- **蒸馏找不到角色**：补完整作品名、版本或明确资料链接，核对候选包含正文；部分来源站点和不可公开读取页面不会采用。
- **ZIP 没有可读内容**：查看跳过原因；扫描 PDF、图片、密码包或超限文件需先转换或拆分。

一键自检先读取本地配置与状态，不代表真实 QQ 收发或模型质量已经验证。需要排查时查看运行记录，向他人提供诊断前使用脱敏导出；不要发送密钥、完整认证地址或原始私人语料。

## 10. 从源码启动

源码版和安装版共用界面与核心，不需要 Node、Git 或前端构建。Windows 先安装 Python 3.11–3.13（推荐3.12），在源码根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup-source.ps1
```

首次安装依赖需要网络，脚本创建项目内 `.venv`，默认数据仍保存在独立用户目录。之后启动或停止：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Stop
```

想要独立数据位置，首次、日常启动和停止都使用相同的 `-DataDir 'D:\shiori-data'`。

只准备环境使用 `-SetupOnly`；依赖缺失时使用 `-Reinstall -SetupOnly`。停止可用 `powershell -ExecutionPolicy Bypass -File .\scripts\setup-source.ps1 -Stop`，也可从管理台或托盘退出。

完整迁移、手动部署和实验性 Linux 路径见[源码部署指南](https://github.com/iownmmiku/Shiori/blob/main/docs/SOURCE_DEPLOY.md)。Linux无头核心已通过GitHub CI，真实QQ与长期部署仍需在目标环境验收；默认只绑定回环地址，远程访问需要密码与受保护网络。源码 ZIP 不包含用户数据、已登录 QQ 或任何可用密钥。

## 11. 调度与外部环境验收

设置中的请求调度可调整每模型并发、前台/后台排队容量与每会话消息队列。默认每模型并发1、模型排队32、后台排队16、会话排队8；队列满时明确提示，前台优先。SQLite 使用 WAL 与索引读取，仍仅允许单实例写同一数据目录，不支持多节点共享此目录。

源码提供真实本地 TCP 故障回归与人工发消息的真实环境验收入口。不要把替身协议通过视为真实QQ账号、风控或模型质量已经验收。运行方法见[源码部署指南](https://github.com/iownmmiku/Shiori/blob/main/docs/SOURCE_DEPLOY.md)。

## 选择GitHub版本与更新

在右上角“版本与更新”检查 GitHub 版本，选中目标后点击“切换到 v…”。软件在后台获取和校验程序文件，备份数据、替换程序并自动重启，不需要另行下载、解压或运行安装器。下载阶段可以取消，交接前需先完成或停止后台任务。

“管理更新占用”可查看历史下载和恢复备份的大小，逐项确认后清理可删除的旧目录。当前任务、最新成功恢复备份和恢复结果未确认的目录保留；旧目录缺少管理记录或包含链接时不会自动删除。

0.2.0 起，Windows 安装版、便携版与非容器源码服务使用 `iownmmiku/Shiori` 作为更新源。默认显示正式版，可开启测试版或翻页查看历史版本。旧 `mikubot-…` 发行资产仍位于 Shiori 的发行页；原 0.1.6 beta 保留原包与校验值，仅供手动历史下载。

源代码有本地修改、磁盘空间不足或目标版本缺少校验信息时不会覆盖。未声明数据库降级兼容性的历史版本只能下载，不能直接覆盖。远程切换需在运行电脑上授权，或由宿主管理员配置 updates.allow_remote。Docker通过镜像更新。升级前退出旧实例，另存完整数据目录、原始材料、插件与电脑工作目录；不要让试用实例与正式实例共用数据目录。

**0.1.6 及更早版本无法在应用内安装 0.2.0。** 它们会读取没有安装文件的旧占位仓库。先退出旧实例并备份完整数据，再从 Shiori 的发行页下载安装包，选择原安装位置；便携版应完整解压到新目录，源码部署按原方式更新。继续使用原数据目录，自定义位置可通过 `--data-dir` 指定。不要让新旧实例同时写同一份数据。

详细步骤和限制见[更新指南](https://github.com/iownmmiku/Shiori/blob/main/docs/UPDATES.md)。


## 本地插件与数据统计（0.1.3）

“管理功能 → 插件”默认提供“导入插件包”和“用聊天创建”，支持 ZIP、tar.gz、tgz 自动识别，旧插件继续兼容。先连接支持工具调用的模型并开启电脑能力，在本地聊天描述目标可生成规范草稿，检查后启用；有明确“创建并运行”要求且已开启自动执行时可连续完成。运行参数优先显示表单，复杂参数也可输入 JSON。代码定义同步 `run(input)`，返回 JSON 结果。每次修改重新停用，不自动装依赖。QQ用户不能创建或运行这些插件。任务遵循电脑能力的运行环境、审批与停止规则；自动模式不增加逐项批准，源码和产物另行备份。

规范包包含`plugin.json`、`main.py`和`README.md`，可附辅助模块和资源。上传先列出候选，单项失败不影响其他合法候选；过深的Python表达式会提示文件及拆分建议。修改已有插件时可在本地聊天明确说“修复 example_plugin 插件的重复输出”；模型先读取代码与修订信息，保存时核对版本，避免覆盖别处的修改。新建不能覆盖已有ID，修改后核对并重新启用，不自动运行。格式和容量限制见[插件说明](https://github.com/iownmmiku/Shiori/blob/main/docs/PLUGINS.md)。

“数据统计”显示1/3/7天消息、平台分布、模型调用与Token趋势，以及进程CPU、内存和运行时间。0.1.4记录流式首个有效内容延迟，没有真实样本时不显示虚构值；价格未知会标明，估算费用不等于服务商账单。

“系统设置 → 时间与日配额”可填写 IANA 时区，例如 `Asia/Shanghai`、`UTC` 或 `America/New_York`。默认Asia/Shanghai（UTC+8），日预算、Planner、表情包配额、统计及自然语言提醒使用该时区；单个提醒可保存独立时区，重复提醒按当地日历处理夏令时。

表情包页显示“识图+发送前选图”的统一模型调用配额，默认每天60次，另保留每日30次识图上限；失败也占一次尝试，0停止对应调用。页面同时显示两类次数、Token和下次重置时区。350/120只是两类模型请求的最大输出Token设置，实际还含输入及服务商收费，不能把次数当作固定账单。

插件与统计从0.1.3提供，规范包导入和聊天修改流程在0.1.6完善；旧版请先升级。

## 模型生成时自然分段（0.1.3）

在“机器人配置 → 回复与记忆”选择默认的“模型自然分段”：模型在生成回复时用空行决定另发一条，单换行只是同一条内排版。一条可以几个字，也可以包含好几句话，不强制发满固定段数；模型没有主动分段时整条发送，不按字数补切。本地聊天也按生成时已保存的边界显示。

完整代码围栏内的空行与完整JSON保持一条。0.1.4在超出连续条数上限时均衡合并相邻模型段落，不把长尾全部堆到最后，也不按句子补切单个模型段落。仍保留平台长度保护；无法完整容纳受保护内容时停止并保留原文。每条发送继续检查权限、来源和回执，失败停止后续条，不自动重发。旧版目标段长只在主动选择“旧版按长度分段”时生效。

## 0.1.4 资料、检索与增量回复

本地聊天会逐步显示模型回复草稿，完成后以校验后的最终结果替换；工具调用或取消时可能清空草稿。不要把尚未完成的预览当成已经执行的操作回执。

模型触发内容过滤时显示统一提示，清除临时草稿，不发送上游报错正文或执行该响应的工具；不会因过滤自动切换备用模型。已发生的调用仍记录用量，缺少服务用量时标为待核实，详情见[模型响应说明](https://github.com/iownmmiku/Shiori/blob/main/docs/MODEL_TRANSPORT.md)。

资料上传可选择本次参考、长期资料或人格蒸馏；资料管理支持预览、撤销与清理，详情见[附件说明](https://github.com/iownmmiku/Shiori/blob/main/docs/ATTACHMENTS.md)。大量记忆首次会分批建立词项索引，缺失向量默认后台补建，仍会产生嵌入调用费用；[检索说明](https://github.com/iownmmiku/Shiori/blob/main/docs/MEMORY_RETRIEVAL.md)介绍等待预算和队列边界。

“设置与连接 → 资源与响应速度”提供低内存预设和有界并发参数；“数据统计”展示后台索引与当前可读取的容器资源。已收到的Token、估算和待核实消费分开显示，本机可记录人工核对，尚不支持供应商自动逐笔对账。模型流式、超时与备用调用设置见[模型响应说明](https://github.com/iownmmiku/Shiori/blob/main/docs/MODEL_TRANSPORT.md)。

### 回复长度与括号内容

打开 **机器人配置 → 回复与记忆 → 回复内容与消息分段**，可设置整轮回复字符上限`output.reply_max_chars`、单条消息字符上限`output.message_max_chars`；默认均为0，不限制。“删除括号及其中内容”对应`output.remove_parentheses`，默认关闭。会话不单独覆盖时继承全局。

字符数包含中文、英文、标点和空格，不计换行。优先让AI生成时遵守；超出时缩短展示，可展开原始回复。代码、链接和JSON不截成残片，无法放下会提示查看原文；未匹配括号保留，只处理AI正文，系统指令和工具确认凭据保留。内容规则开启时增量预览按安全完整段出现，末段等最终结果。完整边界见[输出说明](https://github.com/iownmmiku/Shiori/blob/main/docs/MODEL_OUTPUT.md)。


## 事件记忆（0.2.1-beta 本地开发）

打开 **记忆档案**，可以按“事件、事实、偏好、笔记”筛选。事件卡片先显示概述；点击详情查看完整经过、参与者、地点、结果和原消息来源。来源可翻页，无法核验、已删除或已修改的原消息会明确提示，不能当作可靠证据继续展示。

新增记忆默认采用事件表单，只需填写经过；标题、概述、参与者、地点和结果均可留空，也可以切换成事实或偏好。自动整理会按经历保留过程与结果，仍受学习开关、来源校验、审核及每日额度约束，不保证每条聊天都成为记忆。

事件发生时间不明确时显示“时间未确认”，不会用保存日期冒充。旧版的一句话记忆保留原文；可以手动选择“整理为结构化事件”补全已有资料，系统不会自动补造缺失的经历。管理台汇总查看仍不改变聊天之间的记忆隔离。

## 0.1.5 学习与管理功能

0.1.5 支持后台直接替换和重启，更新范围、远程授权、源码修改保护及历史版本限制见[更新指南](https://github.com/iownmmiku/Shiori/blob/main/docs/UPDATES.md)。

记忆档案默认汇总全部会话，显示每条记忆的来源会话；页面上方明确标出查看范围，可以切换为只看当前聊天。统计与七日新增图跟随同一个范围，搜索和状态筛选继续生效。这个管理视图不会改变机器人召回记忆的隔离规则。群语言页独立选择查看范围。点开“学习与审核设置”可控制自动确认、空闲整理和群词隔离；群词默认共享的是确认后的词义，私聊及原始例句仍隔离。在管理台顶部选中对应 QQ 会话后，打开“记忆档案 → QQ 分段发送记录”，可区分已确认、送达未知和从未发送，并经确认补发从未尝试发送的后续；QQ 聊天管理监控页仅查看，不发送或补发。

补发前还会核对原始请求、上下文、回复及权限。恢复备份后内容或时间已修订时，旧正文不能继续补发；缺少原始校验信息的旧版发送记录保留查看，但需重新提问生成回复。已确认和送达未知的段落不会自动重发。

人格编辑中的“角色资料（选填）”支持居住地、职业、年龄、生日、作息、背景和关系称呼；留空不会自动编造。
